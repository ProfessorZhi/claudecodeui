## 背景

2026-09-24 的三次真实失败暴露了同一个缺口。页面上分别显示 transcribe 404、transcribe 502、transcribe 422，而真实原因是我方把共享 backend 的模型名发给了 DashScope、上游 403 的账号未开通或欠费、以及模型给出了空答案（多半录音里没有语音）。三者要用户做的事完全不同（无法自己处理、去控制台开通或充值、重新录音），页面却给了同一种不可行动的英文句子。

现状有五个问题。前端丢掉了服务端已经算出的说明，只拼状态码。只有上游之前的三种拒绝带错误码，理由是传输层失败没有按原因选择补救的差别，这个前提已被上述事故推翻。文案是硬编码的英文，十二个语言里都没有错误键。提示只显示 4 秒，读不完带补救措施的句子。同一件事（没有语音）在空的 200 结果和服务端 422 上有两种说法。

对照阿里云百炼官方错误码页，现有映射还有几处对不上：欠费是 400 的 Arrearage，配额与免费额度耗尽是 429 的 AllocationQuota 类却被当作稍后重试，模型不存在的 404 丢了模型名，音频时长与内容审核的 400 都落在通用 400 里。人 yale 2026-09-24 裁定采用提案的全部建议，设计见 docs/proposals/voice-error-messages.md。

## 范围

- 反转传输层失败只带文字的决定：语音转写路由的所有失败都返回稳定的 code，上游失败另带只含枚举串的 upstreamCode，不含响应体的其他文本，不含 key。
- 词汇表按证据扩充：ACCOUNT_ACCESS（未开通、欠费、授权失效合为一类）、QUOTA_EXHAUSTED、MODEL_NOT_FOUND、AUDIO_REJECTED、CONTENT_FLAGGED、UPSTREAM_UNAVAILABLE，保留既有的码；适配器依据响应体里的错误码串分类，无码串时按状态兜底；每个 code 在状态表里恰有一行。
- 分类做成共享识别目录里的单一实现，浏览器直连路径与代理路径复用，两条路径对同一上游失败给出同样的 code。
- 前端按 code 选取本地化文案（说明发生了什么与怎么办），十二个语言齐全并有兜底文案；空的 200 结果与 422 都显示同一条没有语音的文案。
- 提示持续显示到用户关闭或开始下一次录音，带一行折叠的技术详情（状态码与 upstreamCode），composer 里的草稿保持不变。
- 同步修订 ADR-004 的错误码词汇表与 voice.service.ts 里传输层失败不带码的注释及相关测试。

## 非目标

- 不做上传前的静音检查：误判会丢掉真实口述，且应先用 GOAL-010 的捕获数据看清 422 的实际成因。
- 不做失败后的自动重试，不做一键打开设置之类的跳转按钮。
- 不改 voice.transcribe 日志行的形状（AC-143 要求关闭态下它与基线逐字节相同）。
- 不改变识别本身的行为、提示词或模型。

## 退出条件

- AC-149 分类：夹具逐行的（上游状态、响应体码串）分类为预期的 code，同状态不同码得到不同分类，状态表对每个 code 恰有一行。
- AC-150 契约：经出货路由，所有失败都带 code，上游失败带合规的 upstreamCode，响应里没有 key 与上游响应体的其余文本。
- AC-151 文案：每个 code 在全部语言里都有非空文案，有兜底文案，文案不是拼接的状态句。
- AC-152 单一实现：直连路径与代理路径对同一批夹具得到相同的 code，分类只有一份实现。
- AC-153 真实浏览器：各类失败显示各自的文案，提示持续显示到关闭，草稿保留，技术详情折叠。

## 不做退出条件的范围内事

- ADR-004 的词汇表修订与 voice.service.ts 注释的更新：属于决策记录与注释，不设判据，由任务 2 承担。
- GOAL-010 的 text 档捕获落地后，voice.capture 行增加 code 与 upstreamCode：依赖 GOAL-010 的实现，是本目标的收尾项，不另设判据。
- 各语言文案的措辞质量属于人读范畴，判据只要求存在、非空、非英文语言不与英文逐字相同。

## 已知不等价点与限制

- 官方错误码页是通用表，个别条目（如音频时长 1 到 300 秒）对 qwen3.8-omni-flash 的聊天音频输入是否适用没有验证；分类以响应体码串为准、状态兜底，表外的码会落到兜底而不是被错误归类。
- 未开通与欠费合成一类，用户看到的补救是开通或充值，不区分；这个账号实际两种情形混在一起。
- 与 GOAL-010 的任务在 voice.service.ts 上有交叠，合并时可能需要处理冲突。
- 全部判据跑在 Node、替身上游与 Playwright Chromium 下，不等于真实 DashScope 与真机浏览器。
