## Proposal

**交付物：外部写入路径的驱动与判据——「有人（或某个脚本）直接往 transcript 文件追加行，app 仅旁观」这条链路的可复现覆盖。** 据 `adr/ADR-003-可控制的调试-agent-不跑真-cli-也能产生输出.md` 决策 5 实现与判据化。

**这是今天的零覆盖区，也是立 ADR-003 的主要理由之一。** 今天能端到端产生一次真实输出的路径只有真 CLI 进程，而既有的浏览器侧替身只替换 `window.WebSocket`、只注入 `stream_delta`/`stream_end`，**完全跳过后端**。会话被外部写入、app 仅旁观这条路径（文件观察者发现变化 → 广播 `session_upserted` → 客户端按 REST 重取整行）在 e2e 里**一条都没有**。而它的后半段（`session_upserted` → REST 重取）**没有 runtime 参与**——这正是它不被「app 自己产出」那条路径覆盖的部分，也是它必须被单独驱动的原因。

**驱动方式走既有的旁路语义**，即"不要替这个会话做同步，只观察"；实现上对应观察者只对文件变化反应并广播，不经过 runtime。

**判据必须自己排掉一个干扰源（本任务最容易写错的一处）。** **装载场景这一步本身就会产生一次 `session_upserted`**——观察者把刚写下的种子文件读成 `add` 事件，最多迟一个轮询周期才广播。因此「等到一个 upsert 就放行」是**盲判据**：它会被装载那一次满足，外部写入根本没被证明。现场第一次写这条判据时**正是这样被骗过的**——量到的 2.3 秒其实是装载事件（见 `adr/ADR-003-验证记录.md` 的 d）。判据必须按三步写死：

1. **先排空**——等到没有新 upsert 且静默超过一个轮询周期；
2. 再追加，并要求一条**新的** upsert；
3. 以观察者**自己的日志行**（`change event for provider …`）作**正面控制**，证明这一条确实走了观察者而非别的路径。

**时间预算的读法（也是现场实测纠正过的一条）。** 观察者的轮询间隔是 6 秒、项目更新的去抖是 500 毫秒，两者串联最坏接近 6.5 秒并受调度抖动影响——因此观测窗口**不得小于 8 秒**。但 8 秒是**安全上界、不是下界**：实测 4 个样本落在 1.7–3.1 秒，所以写成 5 秒的判据**不会**红——说它"必红"是错的。留 8 秒的理由是它把最坏情形也包住；写成更小值是在赌轮询相位。

**本任务不做**：不实现引擎（另有任务）；不实现门控（只消费它给的观察根）；不实现控制面。

**同机制去重结论（仅溯源，不构成前置）**：`tasks/` 内无同机制任务——按「外部写入 / 观察者 / session_upserted / 旁路」检索无命中。相邻但机制不同的是**贴底跟随「整行到达」那一族**（同族已有 GOAL-004 的六条 achieved 判据与一条 ready 任务）：它们也用「外部写入的会话」作为**夹具**，但测的是**贴底跟随的几何行为**，不是送达链路本身。两者不重复——本条按评审裁决 C 与贴底一族解耦，**不以其中任何一条为前提，也不因它们未完成而等待**。

## Plan

1. 夹具：在门控给出的 fixture 根下种一个会话并索引它，使该会话可被 REST 寻址；随后**由测试自己**（不经过 app 的任何接口）向该 `.jsonl` 追加一行——这正是"外部写入者"的形状。
2. 观察者必须真的在跑：断言观察者对该文件的 `change` 事件出现在服务端日志里，而不是只断言客户端收到了广播。
3. 判据按 Proposal 的三步写死；第 1 步的"静默"以**超过一个轮询周期**为准，不用固定 sleep 猜。
4. 观测窗口 ≥8 秒，但**不断言**实际延迟必须 ≥8 秒——只断言"在窗口内送达"。
5. 送达之后还要断言 REST 重取结果里**含**那条外部追加的内容（广播到达 ≠ 历史到达）。

## AC

- [x] AC1 外部写入判据——`npx tsx --tsconfig server/tsconfig.json --test server/modules/debug-agent/tests/debug-agent-external-write.test.ts` 退出码 0。该用例即 `goals/AC-125`：按 (i) 排空装载那一次 upsert、(ii) 追加后要求一条**新的** upsert、(iii) 以观察者日志的 `change event for provider …` 行作正面控制 三步执行，并断言外部追加的内容出现在 REST 重取结果里。打印每一步的实际读数与耗时。
- [x] AC2 抗假变体（**真跑并留输出**）：**绕过网关**——不经过观察者与广播，直接写库或直接改客户端状态。`AC1` 的命令必须因此**退出码非 0**，且红因是 (ii)/(iii) 同时不成立。**同时贴出"只断言出现了一个 upsert"那版判据在本变体下仍然绿**的读数——那条盲判据是被装载事件顶掉的，本 AC 用它证明修改是必要的。跑完还原，`git status` 干净。
- [x] AC3 时间预算的读法被如实登记：命令打印本次运行的实际送达耗时，并在完成记录里写明"8 秒是上界不是下界"这一读数（实测分布 1.7–3.1 秒）。取假形态：把窗口写成 1 秒时必须**偶发红**——若恒绿，说明夹具的相位是定的、判据测的不是观察者。
- [x] AC4 排空步骤本身被证明有效：命令打印"排空后静默时长"与"排空期间观察到的 upsert 次数"，使 (i) 不是一句空话。取假形态：删掉排空步骤时 `AC1` 必须有可能在外部写入**尚未发生**时就放行——本 AC 用"装载事件与外部写入之间的时间差"把这个风险变成可读数字。
- [x] AC5 本任务未触及 Touches 之外的文件。命令：`git diff --name-only "$(git merge-base develop HEAD)"` 的每一行都必须能对应到 Touches 内的一条；命中之外时逐行打印并以非 0 退出。

## DoD

真实落地判据（不是「收到过一次广播」）：**外部写入这一条链路，从文件变化到 REST 重取可见，全程被证明走的是观察者。** 承重性由三件事正面证明：

(a) **判据自带排空**（AC1 的 (i)）——否则它会被装载那一次顶掉，现场已经这样被骗过一次；
(b) **有正面控制**（AC1 的 (iii)）——没有它，「绕过网关」的假实现与真实现无从区分；
(c) **抗假变体真跑过**（AC2），且附带"盲判据仍然绿"的对照读数，证明这次修改不是修辞。

另需如实登记：本任务**未覆盖**观察者的边界语义（例如 `pruneOrphanedSessions` 的目录存在性边界——那在 fixture 隔离任务里）；也**未覆盖**真实外部 CLI 写入（夹具是测试自己写的文件，形状相同但来源不同）。

L_D 该轴仍暗，理由：本任务交付的是调试/测试机制的一条送达链路覆盖，不改变产品领域能力，没有可读出的产品领域读数；判定面由 AC1 的三步读数与 AC2 的对照承担。
L_G 本目标的判据是 `goals/AC-125`（外部写入经真实文件观察者送达客户端，判据自带排空与正面控制），本任务的 AC1 即该判据的命令；AC2 是它的抗假变体。
