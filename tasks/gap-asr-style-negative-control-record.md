## Proposal

<!-- dedup-ref --> 同机制去重结论：全仓无任何任务声明与本条同一机制；`task_list` 全文检索「风格化」无命中。与本条相邻的是同为 ADR-004 后续任务的「第二个适配器」（AC-132）与「两跳字节基线」（AC-130）两条，机制不同 —— 两条都不做「含文件路径与代码片段的句子经风格化后标识符逐字保留」这条负对照。本任务是 ADR-004「后续任务 8」的立案；本条**不引用任何未完成任务 id 作为前置**。

**性质（ADR-004 决策 8）：本条产出的是实验记录，不是 AC 判据。** 它要求一个 `style: written` 的识别服务，**联网且需要凭据**，按决策 8 不进判据集。因此本任务**不设 `depends_on`** —— 它是实验记录，其可执行性由外部条件（一个可达的 `style: written` 服务 + 凭据）决定，而不是由任务依赖图决定。

**现场。** ADR-004 决策 5 把输出信封扩为 `{ text, style, transformations }`，而现有的标识符度量量的是**逐字存活**（大小写与点号敏感），一份书面化文本本来就不逐字等于口语原话 —— 于是现有判据会**失明或失义**。ADR 决策 5 因此要求一条**能红的负对照**：含文件路径与代码片段的句子在风格化之后必须**逐字保留**（书面化最容易顺手把 `voice.service.ts` 改写成 `voice service ts`）。按人 yale 2026-09-22 的裁定 2，这条负对照是**机检那一半**，必须在同一 runner 内与质量读数并列 —— 质量半人读，安全半机检。

**本任务做什么。** 一份实验记录，含：一条含文件路径与代码片段的句子，经风格化后其中的标识符**逐字保留**；同时记录「风格化确实发生了」的证据（`transformations` 非空且与实际改写一致）。**两个方向都要能红**：惰性实现让「确实发生了」失败；把标识符一起改写让「逐字保留」失败。记录的协议沿用 `docs/experiments/README.md`：配对比较不跨运行、必须有能红的负对照、被测实现必须是出货模块、报 `n`、串行执行、结果落盘缓存。

**边界（不做）。** 不改任何出货代码（本任务只落记录与驱动它的 runner）；不把质量读数做成 CI 判据（决策 8）；不做裁剪 × 能力接线；不做配对质量实验记录（那是「后续任务 10」）。

## Plan

- **S0 语料。** 一条含文件路径与代码片段的句子（例如含一个源码符号名），固定下来。
- **S1 runner。** 驱动 shell（`style: written` 服务，联网 + 凭据）取两向读数：`transformations` 是否非空且与实际改写一致；标识符是否逐字保留。两个「假实现」（惰性、把标识符一起改写）各成一条可红控制。
- **S2 记录。** 按 `docs/experiments/README.md` 的协议写记录：配对比较不跨运行、报 `n`、报告负对照是否按预测方向移动、串行执行、结果落盘缓存。
- **S3 留档。** 记录落在 `docs/experiments/`，并在 `docs/experiments/README.md` 登记。

## AC

- [x] AC1 **机检负对照（安全半，离线，用假实现）**：惰性实现（风格化根本没发生）⇒「确实发生了」那一半必须红。
- [x] AC2 **机检负对照（安全半，离线，用假实现）**：把标识符一起改写的实现 ⇒「逐字保留」那一半必须红。
- [x] AC3 记录含一条含文件路径与代码片段的句子，以及它在**真实** `style: written` 服务下风格化后的文本（联网 + 凭据；这一步是本记录的**读数**，不是 CI 判据）。
- [x] AC4 记录含 `transformations` 非空且与实际改写一致的证据；两个方向都留读数（惰性 ⇒ 「确实发生了」失败；标识符被改写 ⇒ 「逐字保留」失败）。
- [x] AC5 记录按 `docs/experiments/README.md` 协议写成：报 `n`、配对比较不跨运行、串行执行、结果落盘缓存，并报告负对照是否按预测方向移动。
- [x] AC6 **不判据化（ADR-004 决策 8）**：本任务整体不进判据集 —— 它联网、需凭据、且需要 `style: written` 服务；不得把「记录里提到了某个词」当作任何判据。
- [x] AC7 不改任何出货代码：本任务的 diff 只落在 `docs/experiments/`（新增记录 + README 登记）与 `experiments/voice-style-negative-control/`（新增工装）两个目录内，不含任何 `src/`、`server/` 或 `scripts/` 下的文件。

## DoD

真实落地判据：不是「多了一份 md」，而是**这条负对照在两个方向上都能红，且质量读数与安全读数并列在同一 runner 内**（裁定 2 的要求）。承重性由两件正面读数证明：

(a) 惰性实现 ⇒「确实发生了」那一半红（AC1）—— 否则一个根本没做风格化的实现会让整条判据全绿，那就是「没有测量任何东西」；
(b) 把标识符一起改写的实现 ⇒「逐字保留」那一半红（AC2）—— 这是决策 5 点名的失效形态。

**本任务不证明**质量更好（那只能靠人读配对文本），也不把任何质量数目做成 CI 判据（决策 8）；它只把「风格化没有吃掉标识符」这条安全半做成可红读数，并如实留档。

**如实登记：** 本任务联网且需要凭据，其读数随服务与语料变化；按 ADR-004 决策 8 与裁定 5 的代价登记，质量回归不会被自动发现，依赖「每接入一个服务就写一份实验记录」这一人工义务。

L_D 该轴仍暗，理由：本任务只产出实验记录与一条双向负对照，不新增领域数据能力，也没有可读出的领域读数。
L_G 该轴仍暗，理由：同上 —— 目标层判据（换识别服务不改路由与 UI）由 GOAL-008 的其余判据承担。
