目标记录：GOAL-006（AC-116 … AC-122）
证据基础：本轮现测，工装 `/data/home/yale/work/tc-verify`（`tools/vad.mjs`、`tools/compress.mjs`、语料 `corpus/dictation` 与 `corpus/dictation-en`）

## 摘要

在音频送识别器之前，把**静音**裁掉：先 VAD 判定语音段，再做边界裁剪与长停顿 cap，**α 恒为 1（不调用任何变速）**。
实测账单口径中文省 **25.5%**、英文省 **13.3%**；标识符逐字存活率**中性**，代价是 CER +1.1% 与句读标记 2.06 → 1.00。

不做 WSOLA：在停顿裁剪之上只再多省 **2.8pp**，却把句读再压到 0.56，而 α=0.8 在中文把标识符打到 **0/12**。压缩留待后续单独立目标。

同时落地三件可观测/可复现能力：裁剪与原始**两条回放**、开关控制的 **console 裁剪读数**、开关控制的**音频文件上传入口**（走同一条转写链路，供复现与自测）。

## 背景与现状

push-to-talk：一次按键 = 一段录音 = 一次请求。`useVoiceInput.ts` 用 `MediaRecorder` 把整段录音编成 blob，`src/shared/api.ts` 的 `transcribeVoice` 原样上传（配了 `baseUrl` 时浏览器直连，否则走服务端纯透传代理）。

这段音频里要付钱的部分：按键到开口、说完到松手、以及句子之间的思考停顿。Groq 的 STT 按音频秒数计费且**不足 10 秒按 10 秒计**，另有一个按真实音频秒数扣的配额账本。

2026-09-21 的实测排除了两条更早的候选：噪音处理链路（VAD 在 ≥10dB 稳健，且浏览器 APM 已开 `noiseSuppression`/`echoCancellation`）与识别时上下文 / prompt 偏置（n=7 证据不足）。剩下的杠杆就是时长本身。

## 目标与非目标

### 目标

1. 送识别前的音频被裁短：只删静音，**不删任何 VAD 判为语音的样本**。
2. 异常必兜底：VAD 段数为 0 或覆盖异常时，回传原始音频，绝不因此丢掉一次听写。
3. 裁剪在**客户端**完成，服务端契约不变（直连模式下服务端本就不在链路上）。
4. 链路可观测（开关控制的 console 读数）且可复现（开关控制的音频文件上传入口）。
5. 裁剪与原始**两条回放并存**，人能核对剪掉了什么。

### 非目标

- WSOLA / 时间轴变速，含已验证安全的 α=0.9（收益 +2.8pp，句读 1.00→0.56）。
- 识别时上下文 / prompt 偏置（证据不足，另议）。
- 改 `server/modules/voice/` 的接口契约：保持纯透传。
- 改默认交互：上传入口与裁剪读数默认不可见。
- 采集真人语料：本轮仍是 TTS + 参数化注入的停顿。

## 推荐架构

```
MediaRecorder → Blob ─┬─→ 回放槽（原始，object URL）
                      │
                      └─→ decodeAudioData → Float32Array
                                │
                                ▼
                     voiceTrim.trimVoiceAudio()   ← 纯函数：VAD + 边界裁剪 + 停顿 cap
                                │                  （无 DOM、无 IO、无模型）
                                ▼
                          重编码（webm/opus 或 wav）
                                │
                                ├─→ 回放槽（裁剪后，object URL）
                                └─→ transcribeVoice() → 修复 → composer
```

| 层 | 位置 | 说明 |
|---|---|---|
| 纯 DSP | `src/shared/voiceTrim.ts`（新） | `Float32Array` 进、出 + `stats`；Node/vitest 可测；与 `src/shared/identifierRepair.ts` 同层同风格 |
| 浏览器适配 | `src/modules/chat/utils/audioDecode.ts`（新） | `decodeAudioData` / 重编码，只有它碰 WebAudio |
| 挂载点 | `src/modules/chat/hooks/useVoiceInput.ts` | 上传前调用；读数在此产出 |
| 入口与回放 | `src/modules/chat/composer/*` | 麦克风旁的开关控制上传入口；录音槽两条回放 |
| 开关 | `src/shared/voiceDebug.ts`（新） | URL `?voiceDebug=1` ∪ localStorage `voice-debug=on`；命中 URL 时写回 localStorage |

**为什么在客户端**：配了 `baseUrl` 时浏览器直连用户的识别端点，服务端不在链路上；且 GOAL-005 已把「服务端纯透传」立为契约。

## 测试与验收标准

见 GOAL-006 的 AC-116 … AC-122。三条原则：

1. **被测实现必须是出货模块**（`src/shared/voiceTrim.ts`），harness 不得自带第二份算法 —— 这条代价已经付过一次（AC-113 的旧判据量的是副本，与出货模块 16 条里 6 条不一致）。
2. **「省了时长」与「质量不降」必须同时断言**，否则恒等实现能靠质量那一半拿分。
3. **零值要有正对照**：同一个 runner 里打印不裁的基线行。
