## 目标

1. 在日志回放上，"丢失 ≥7 字的实质内容"明显低于 settle producer，同时识别原文占比不高于 settle producer。
2. 规则是**纯函数**：输入是转写序列与已执行消息序列，输出是补发列表，可以直接用日志回放测试，不需要网络。
3. 不依赖语种识别，对中、英及其他大语种一致工作；对未验证语种不应乱补。

## 非目标

- 不修复模型本身丢话的原因（取消、span 消费、端点不建 response 等）；那是 `interrupt_response:false` 与提示词的事，见「配套设置」。
- 不补 ≤6 字短句，不做标识符修复。
- 不引入新 UI；不要求模型输出时间戳、编号、声明。
- 不改 Claude Code 一侧行为。

## 术语与输入

- `F_i = (t_i, x_i)`：第 i 条最终转写（`transcription.completed`），到达时间与识别文本。空串（归一后）的转写不计入。
- `M_k = (τ_k, m_k)`：第 k 条**已执行**的中继消息，取自 `session_send` 与 `session_interrupt` 的 `message`，且所在 response 为 `completed`。所在 response 被新语音取消（`cancelled`）的调用没有执行，**不是** `M`。
- `SS`：`input_audio_buffer.speech_started` 的到达时间序列（代理已有）。只用于判定时刻的「沉默确认」分支（§3），不参与覆盖度。
- 以上输入代理均已拥有，无需新增采集。

## 规则 v2（规范性）

### 1. 归一化 `analyse(s)`（不做语种识别）

1. NFKC，然后 casefold。
2. 删除数字：只删**连续 ≥2 个数字字符**的串（`\p{Nd}` 与中文数字串 零〇一二三四五六七八九十百 同算）。单个 一/二/3 保留为词，因此「一些、一下」不再因丢字掉出资格。两侧（`x` 与 `m`）同一规则，数字内容不参与覆盖判断。
   - 备选「删所有数字字符」与「仅在量词前后删」的回放比较见「证据」；选定 `runs2`（连续 ≥2）因为重复与丢失两项都最低。
3. 对拉丁、西里尔、希腊文字：NFD 后去掉组合附加符（Mn），使 café/cafe 这类识别差异不影响比较。
4. 去掉所有标点、符号、空白（凡非字母、非附加符的字符，作为词的分隔）。
5. 按文字类型切成单元：
   - 汉字、平假名、片假名（统称 `cjk`）：按出现顺序连成一个流，取**字二元组**。
   - 其他文字：按词（分隔符之间的连续字母）取**词内字符三元组**；不足 3 个字符的词，整词作为一个 gram。
6. 输出：gram 集合 `G(s)`、权重 `w(s) = cjk字数 + 2 × 其他文字词数`、主导文字类型 `dom(s)`。
   - `dom`：若 `cjk字数 ≥ 其他文字词数`，为 `cjk`；否则为字母数最多的那种文字（`LATIN` 等）。按**单元数**（字对词）比较，不按字母数，否则中文句里夹一个英文词就被判成英文。

### 2. 资格：哪些句子可能被补

`F_i` 是候选，当且仅当同时满足：

1. `w(x_i) ≥ 7`（中文约 7 字，英文约 4 词）。
2. `G(x_i)` 非空。
3. **文字不符不补**：取该连接**之前至多 10 条转写**的 `dom` 的众数；若存在先前转写，且 `dom(x_i)` 与之不同，并且 `w(x_i) < 12`，不补（视为识别幻觉）。若接口返回语种字段，实现应优先使用它。

### 3. 判定时刻 `T_i`

- `τ_first` = 第一条 `τ ≥ t_i − 1000 ms` 的已执行消息。
- 若 `τ_first` 存在且 `τ_first ≤ t_i + H`：`T_i = min(τ_first + G, t_i + H)`。
- 否则（到 `t_i + H` 都没有已执行消息）：若用户在 `(t_i, t_i + S]` 内**没有再次开始说话**（`speech_started`），`T_i = t_i + S`；否则 `T_i = t_i + H`。
  - **沉默确认**：等满 `H` 只在这条转写还可能被"关于更新语音的模型消息"覆盖时才有意义。模型完全沉默、用户也没继续说话时，没有更新语音可触发新消息，补发可以提前到 `S` 确认。该分支只改 `T_i`，**不改补发集合**（回放里逐连接的 fills/dup/lost 完全不变）；若模型晚到 `t+S` 之后才回复并覆盖该句，会被 120 s 的重复窗口计入「模型与补发各一次」。
- 参数：`G = 1000 ms`，`H = 12000 ms`，`S = 3000 ms`（扫参见「证据」）。

### 4. 覆盖度与动作

设 `W_i` 为 `τ ∈ [t_i − 1000 ms, T_i]` 的已执行消息集合。

1. 若 `W_i` 非空且其主导文字类型与 `dom(x_i)` 不同：**不可比，不补**（模型可能把语音译成了另一种文字）。
2. 若 `W_i` 非空：`coverage = |G(x_i) ∩ ⋃G(m_k)| / |G(x_i)|`；`coverage ≥ 0.25` 不补。
3. 否则（`W_i` 为空，或 `coverage < 0.25`）：在 `T_i` 把 `x_i` **原文**投递给会话。
   - 同一时刻到期的多条按时间顺序合成一条补发。
   - 补发是单次动作：不询问模型、不重试、无 UI。

### 不属于本规则

- 没有 settle 计时器；一条模型消息**不会**把之前的转写标为已回应（不做 span 消费）。
- 不用 claims、名册、版本回声。
- 水位线（`transcribedSinceWatermark`）的语义是否保留见「接入方式」。

## 配套设置

`turn_detection` 加 `interrupt_response:false`（一行）。实测对取消的影响：24 次响应中取消 8 次 → 30 次中 0 次。但"取消消失后的送达效果"尚未在修好的对照臂上验证（该臂的接线有缺陷，数据作废），见「待验证」。本规则**不依赖**它：回放无法改变模型的行为，规则对取消后丢掉的句子同样起作用。

## 证据（日志回放，免费，`replay_rule.py`）

47 个 continuous 连接、583 条转写；模型行为取自日志，只换投递策略：

| | 识别原文 | 仅模型送达 | 模型与补发各一次 | 丢失 ≥7 字 | 丢失 ≤6 字 | 补发延迟 p50/p90 |
|---|---|---|---|---|---|---|
| 日志实际 | 3% | 74% | 0 | 14.1% | 9.4% | - |
| S settle（生产，模拟） | 7% | 76% | 0.9% | 9.8% | 6.5% | 0.3 s / 5.9 s |
| R v1（仅中文） | 14% | 75% | 2.4% | 1.7% | 9.1% | 12 s / 12 s |
| **R2 v2（本 SPEC，锁定参数）** | 14.1% | 75.0% | 2.2% | 1.9% | 9.1% | **5.2 s / 12.0 s** |

- v2 比 v1 少补 2 条（82 vs 84）：`runs2` 数字处理保住了含"一"的短句，但没有回到 v1 的资格口径。
- **沉默确认分支的效果**：只改 `T_i`，逐连接的补发集合与 carried 判定完全不变；补发延迟 p50 从 `H = 12 s` 降到 **5.2 s**。p90 仍是 12 s（用户继续说话时仍等满 H）。
- 日志里英文主导的转写只有 13/583，且没有一个纯英文会话；v2 在它们上补 0 条。**v2 在英文与其他语种上的精确率无数据**。
- **人工标注精确率（本回放读数，非检测器评估）**：`--check-labels` 把 82 条补发按（连接前缀，识别文本）对到复核单 64 条，命中 33 条；其中有 O/D 标注的 22 条里 O=20、D=2，**精确率 90.9%**（≥ 80%）。被判 D 的两条随 `--check-labels` 打印。
- 模拟 S 在 10-17 之后的识别原文占比（3%）低于实际（12%），S 栏只能当量级参考。

### 参数扫描（`--sweep`，免费）

`H ∈ {4,6,8,10,12}`、`G ∈ {1,2,3,5}`、`SCORE_T ∈ {0.15,0.25,0.35}`、权重门槛 ∈ {6,7,8}，共 180 组。判定可行的外沿：识别原文 ≤ 15%、重复 ≤ 3.6%、丢失 ≥7 字 ≤ 3%、补发延迟 p50 < H。

- **35/180 组可行；H=4/6/8 没有一组可行**（H 越小，覆盖窗口越短 ⇒ 识别原文占比冲到 21–24%、重复 10% 左右）。
- H=10 可行，但最好的一组是 raw 13.6%、dup 2.7%、LOST≥7 2.9%、p50 8.0 s；H=12 的同一档是 raw 14.1%、dup 2.2%、LOST 1.9%、p50 5.2 s。选 **H=12**：重复与丢失都更低，p50 也更低（沉默分支把延迟从 H 上解耦）。
- `G` 在 {1,2,3,5} 上逐连接的 fills/dup/lost 完全相同；取 **G=1** 使 p50 从 7.2 s（G=3）降到 5.2 s，没有测到的代价。
- `SCORE_T=0.35` 也能过（LOST 1.4%、dup 2.2%，raw 14.6%），但离 15% 外沿只剩 0.4 个百分点；保留 **0.25** 的原工作点。
- 数字处理三选一（同一参数下）：`runs2` 82 补 / dup 2.2% / LOST 1.9%；`all` 80 / 2.4% / 2.4%；`quantifier` 81 / 2.4% / 2.2%。选 **`runs2`**。

### 回放门

- `python3 -I experiments/voice-relay-qb/replay_rule.py --check` — 读 `omission-fill-params.json`，只回放冻结的 47 个连接，断言上表外沿与 `p50 < H`。参数文件缺失、任一连接日志缺失、阈值比外沿更宽、任一断言失败 ⇒ 非零退出。
- `python3 -I experiments/voice-relay-qb/replay_rule.py --check-labels` — 由 `flagged-for-review.md` 重新生成标注集（不手抄），命中补发 ≥ 15 且 O 占比 ≥ 80%，并打印被判 D 的补发明细。
- **取假形态**：`--params` 指向 `SCORE_T=1.1` 的参数副本 ⇒ `--check` 红（识别原文 71.9%、重复 58.8%）；`SCORE_T=0` ⇒ `--check` 红（丢失 ≥7 字 6.4%、p50=12 s 不 < H）且 `--check-labels` 红（命中 9 < 15）。

## 已知局限

1. **补发延迟**：多数补发是"模型此后一直没有能覆盖它的消息"。沉默确认分支（`S`）把这种情况的确认提前到 `t+S`，p50 = 5.2 s；但用户继续说话时仍要等满 `H`，p90 仍为 `H = 12 s`。
2. **重复**：模型把含糊识别纠正成正确词后（`reclamation lost` → `connection lost`），覆盖度低而内容已送达，补发的是一份识别错误的重复（已标注 23 条 ≥7 字里 3 条）。
3. **乱序**：补发晚于模型对更新语音的消息。
4. **只在 `T_i` 之后才被带上**的句子会送达两次。
5. **数字删除**的误伤已由 `runs2` 缓解（单个"一"保留），但连续数字串（日期、金额）仍整体删除，其中的"十八日"这类内容不参与覆盖判断。
6. 对译成另一种文字的消息不判断，会漏掉"模型译了别的句子却漏了这句"。

## 接入方式（待人确认）

本节涉及 `server/modules/voice-realtime/`，实施须遵循 `.agents/skills/backend-module-standards`。

1. 新增一个**纯函数模块**（建议 `omission-fill.ts`）：`planOmissionFills(finals, executed, speechStarts, now, params) → fills`，无 I/O；v2 规则的唯一实现。参数从 `omission-fill-params.json` 的 `chosen` 段派生（实现里不要另立默认值）。

5. 日志里需要补一条记录：每次补发的 `{i, T_i, coverage, reason}`，以及每个候选被放过的原因，供回放核对。

## 测试

- **单元**：对 `planOmissionFills` 以夹具表驱动：纯中文、纯英文、中英混说、数字、同文字被译成别种文字、文字不符的幻觉、取消的 response 里的调用、空窗口、边界值（`w=6/7`、`coverage=0.24/0.25`、`t+H`）。
- **回放（免费，每次改规则必跑）**：`replay_rule.py --check` 在**冻结的 47 个连接**上断言外沿（识别原文 ≤ 15%、重复 ≤ 3.6%、丢失 ≥7 字 ≤ 3%、p50 < H）；`--check-labels` 断言人工标注精确率 ≥ 80% 且命中补发 ≥ 15；改规则后两者必须都绿。`--sweep` 打印参数表，用于重新选参。
- **标注对接**：把补发列表对到 `labels.json`，报告标注集上的精确率，须不低于 80%。
- **英文与其他语种**：先由真实纯英文会话产生日志，再回放；在没有语种标注前，只验证"不乱补"（补发条数与重复率不高于中文）。
