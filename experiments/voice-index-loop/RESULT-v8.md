# 结果 v8：SenseVoice 的 `use_itn` / `language` 设置对断句没有改善空间

按 `PREREG-v8.md`（提交 `ba0aa8a5`，读数产生之前）判定。脚本 `sv/punct-settings-eval.py`；原文与识别文本只在仓库外。

## 一句话

**保持现网设置 `use_itn=True, language=auto`。** 没有任何设置在断句上更好：`language=zh` 与 `auto` 持平；`use_itn=False` **完全没有标点**。

## 读数（466 条，v3 同一批 TTS 语音，空隙口径同 v7，只评估对齐匹配处）

| `use_itn` | `language` | 断句 P / R / F1（有无标点） | 句末 P / R / F1 | 逗号 F1 | 字符一致率 |
|---|---|---|---|---|---|
| True（现网） | auto（现网） | 0.904 / 0.789 / **0.843** | 0.911 / 0.692 / **0.787** | 0.597 | 0.862 |
| True | zh | 0.899 / 0.793 / 0.843 | 0.904 / 0.691 / 0.783 | 0.599 | 0.860 |
| False | auto | 0 / 0 / 0 | 0 / 0 / 0 | 0 | 0.840 |
| False | zh | 0 / 0 / 0 | 0 / 0 / 0 | 0 | 0.839 |

## 判定

采纳条件（断句与句末 F1 都不低于基线且至少一项高 ≥ 0.02，字符一致率降 ≤ 0.5pp）：`zh` 的断句 F1 相同、句末 F1 低 0.004，**不满足**；`use_itn=False` 没有标点，**不满足**。

预测核对：P1 ✓（比预测更彻底——不是「变少」而是 0；关闭 ITN 的同时字符一致率也低约 2pp）；P2 ✓（`zh` 对断句无显著改善，±0.004；字符一致率只低 0.2pp，没有明显伤拉丁部分）；P3 ✓。

## 读数里值得注意的

- 现网设置下**精度高、召回低**：句末精度 0.911，召回只有 0.692；即识别器给出的句末标点基本可信，但约 30% 该断的句子没断（这些位置要么没有标点，要么只落成逗号）。
- 逗号类 F1 只有 0.597，但金标是键入标点，逗号风格因人而异，见 v7 局限。

## 局限

1. **语音是 TTS 合成的**：TTS 会在金标标点处停顿，识别器从停顿推断标点比真实口述容易得多，**以上绝对数字偏高**（尤其断句 F1 0.84）；设置之间的比较仍是公平的，但真实口述（停顿少，停顿处不一定是标点）下的绝对水平需要真实录音才能知道。
2. 只测了 sherpa-onnx 暴露的两个设置；模型的其他输入（语言/事件/情绪标记）没有别的对外旋钮。
3. 没测客户端 VAD 的切段（`flushSilenceSec`、最短段）对断句的影响：切段处每段独立识别，每段都会自带结尾标点；这一层与识别器设置无关，是另一个可调的位置。

## 对方案的含义

- 识别器侧的设置已经是最优，不用改。
- 断句要进一步改善，杠杆在**识别器之外**：①客户端 VAD 的切段参数（决定段与段之间是否断句）；②用真实录音和你事后对标点的修改来量，而不是继续在 TTS 语料上调。
