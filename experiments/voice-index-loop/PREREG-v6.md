# 预注册 v6：补做——引擎统一（打补丁的 sherpa）、候选的来源与类型、规模规则、学习回放、声学别名

状态：**在第六轮的 CTC 打分、学习回放与声学别名读数产生之前提交。** 与 v5 的关系：v5 的 S2 / S3 读数用的是「自写前端」，其门槛（文本逐字一致率 ≥ 95%）没过，读数只作方向。本轮把引擎换成**打了补丁的 sherpa-onnx 1.13.8**，文本、token 置信度、逐帧对数概率都来自同一个运行时，自写前端退役。

## 0. 引擎与前端门槛的修订

- **引擎**：sherpa-onnx v1.13.8 源码 + 补丁（`sherpa-patch/sv-logprobs-v1.13.8.patch`，约 185 行）：SenseVoice 的 CTC 贪心解码器返回每个 token 的对数概率（填入已有的 `ys_log_probs`），并在环境变量 `SHERPA_ONNX_DUMP_LOG_PROBS=1` 时导出逐帧的对数 softmax 矩阵（去掉 4 个前缀帧）。本地编译（g++ 13、onnxruntime 1.28.2，与 pip 版同一个 onnxruntime）。
- **已知事实（取数前已测）**：这个模型对极细微的输入差别非常敏感——把波形平移 1 个采样点，约 18% 的片段文本改变；加 −100 dB 的噪声，约 38% 改变。本地编译的补丁版与 pip 版 sherpa 对比，在 1,021 段上文本逐字相同 732 段（72%），差别不来自补丁（解码逻辑未改），来自编译与浮点实现。**所以「文本逐字一致」不是合适的门槛。**
- **新门槛 R0**（三条都要过）：(a) 补丁版自己重复运行，文本逐字相同的比例 = 100%（确定性）；(b) 补丁版的 `ys_log_probs` 与同一段音频上自写前端的最大 softmax 的逐 token 差：中位 ≤ 0.001（交叉核对补丁正确，不是要求前端一致）；(c) 补丁版与 pip 版在**置信度 ≥ 0.85 的 token** 上落入差异片段的比例 ≤ 5%（差异应主要落在不确定的 token 上）。

## 2. 数据与判定

沿用 v3 / v4 / v5：v3 的 466 段（短消息）、金标、靶 token、词源（P / C / U）、判定器（`qwen/qwen3.8-27b`，规则可容忍 + 判定器二分）。对**新引擎的新错误重新判定**（约 530 次调用）。E6 的 461 段只做 R0 与速度，不做判定（沿 v5）。真实录音 20 条只做描述。

## 3. 实验

### R1 统一引擎上重做 v5 的读数
- 有害错误数与率、与 Qwen3-ASR / Omni 的并排（沿用 `sv-summary.mjs`）；
- 置信度：区域级 AUROC（全部 / 有害）、θ ∈ {0.5, 0.6, 0.7, 0.8} 的标记数与召回（含「只标含拉丁字母或数字的段」）；
- CTC：窗口规则不变（p < 0.85，±1 token），候选 = 全部 PCU 实体，排序键 = LLR 与 LLR + 先验（λ = 1.0）；有害错误 top-1 / 3 / 15 召回，对照音近 D1，取并。

### R2 候选的来源、类型、规模
- **来源与类型进入输出**：每个候选带 `{type, 来源集合, 墓碑}`；召回按「正确答案出自哪个来源 / 类型」分解；**墓碑**候选在列表里的占比。
- **规模规则**：每窗口候选池按「近期优先 → 用户词按次数 → 其余」取 K ∈ {200, 500, 全量}；读数：有害 top-15 召回的变化、每条消息的 CTC 打分耗时。**通过条件**：K = 200 的召回 ≥ 全量的 90%。

### R3 学习回放（在 SenseVoice 文本上）
- 回放引擎沿用 v4 E7：臂 T1（词源 + L2a，无学习）、T2（+ 学习，1 次晋升）、T3（+ 学习，2 次晋升）；别名键用保留 CJK 的 `heardKey`；
- 读数：每 50 条窗口的**有害错误残留**、首 / 末三分之一的比值、**学习让有害残留少多少**（T2 对 T1 的相对变化）、重复纠正中被学习修好的个数。

### R4 声学别名
- 回放（学习开）在每条消息之前导出「已确认的 `heard → canonical` 别名」；CTC 打分时，**别名的 heard 写法被分词后作为该 canonical 的额外读法**（候选的似然取各读法的最大值）；若 canonical 不在候选池，则作为新候选加入。
- **对象**：有害错误里「该词此前已有被确认的别名、但这次的误听写法不同」的那部分（重复词、新写法）。
- 读数：这些错误的 CTC top-1 / 3 / 15 召回，有 / 无别名读法对照；全体有害错误的召回变化；别名读法造成的新误报（识别本来对的靶 token 在 LLR 排序里被别名候选顶掉的次数，只报排序，不做替换）。

## 6. 局限（取数前登记）

1. 仍是**真实文字 + 合成语音**；一位用户；理想用户总能发现并纠正；判定器是模型（v4 二分一致率 85%，对新错误未重做盲评）。
2. R4 的对象（重复词、新写法）在 466 段里样本很小，读数只能给方向，置信区间会很宽。
3. 规模规则的排序键（近期 → 用户词 → 其余）是取数前设定的一个版本，没有调参。
4. 补丁版是本地编译产物；模型对编译与浮点差别敏感（见 §0），**部署时必须使用同一份构建产物**，否则同一段音频的文本与置信度可能不同。
5. 补丁里的环境变量开关只用于实验；上游化需要把它改成配置项。
6. 原文、音频、识别文本、置信度与逐帧分布只落仓库外（`tc-verify/corpus/voice-index-loop/`）。
