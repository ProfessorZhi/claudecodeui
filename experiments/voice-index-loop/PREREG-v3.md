# 预注册 v3：基于真实会话输入的「标出—找到备选—自动维护—越来越准」回放实验

状态：**取数（TTS + 识别）之前提交。** 之后改判据、参数、阈值 = 登记为偏差，不得静默改。上一轮（`../voice-context-asr/PREREG-v2.md`）的偏差是「取数后才提交」，本轮纠正。

关系：建立在 `docs/proposals/voice-correction-feedback-loop.md` §5.1–5.7 与 `voice-context-asr/RESULT-v2.md` 之上；音近重打分沿用 `voice-context-asr/pilot/phon.mjs`（参数冻结，不重调）。

## 1. 三个问题

| # | 问题 | 回答方式 |
|---|---|---|
| Q1 | 识别之后，能否**标出**该替换的词 / 短语，并且**备选里真有正确答案**？答案来自哪个词源、哪种实体类型？ | E1：真实输入文本 → TTS → Qwen3-ASR → 带「当时可得」词源的候选生成；按词源做消融 |
| Q2 | 「候选带来源与类型，并自动维护」的机制是否按规则工作（晋升 / 降级 / 过期 / 墓碑 / 冲突 / 会话衰减）？ | E2：对索引机制的确定性断言测试 + 在真实流上回放的不变量检查 |
| Q3 | 随使用「越来越准」是否**收敛**？哪些部分靠学习、哪些靠词源？ | E3：按时间序回放，纠正由规则化的「理想用户」给出，学到的东西只能影响**之后**的消息 |

## 2. 数据（全部来自本机真实会话，原文不入库）

**流 S**：`claudecodeui / quay / quay-fleet / cantus` 四个项目会话里的人写输入，按时间排序（剔除 quay 驱动注入的提示词、续接摘要、任务通知、粘贴块、代码块、URL、UUID / 哈希）。共 1,694 条，其中**入选做语音回放的 N ≈ 486 条**，规则（取数前写定）：

- 清洗后 ≤ 160 字符，至少含 1 个标识符形 token（`[a-z][A-Z]`、含 `_` / `-`、含数字、或 ≥ 2 位全大写），且不含路径 / 文件名（`/`、`.ts` 等：没有人逐字念路径，另作一类，不进本实验）；
- **排除含密钥 / 口令 / 凭据样式的消息**（`passwd|password|token|secret|sk-|Bearer|密码|api key` 后接值等）。被排除的条数与规则在 RESULT 里报告。

**金标**：该条清洗后的文本。**靶 token**：金标里的标识符形 token（形状规则写在 `sim/common.mjs`，取数前冻结）。**错误**：靶 token 没有被逐字（大小写敏感）写进识别文本。

**语音**：用 Edge 神经 TTS 念金标原文（中文句子用 `zh-CN-XiaoxiaoNeural` / `YunxiNeural` 交替，纯英文用 `en-US-AriaNeural`）。**局限在 §8**：这是「真实文字 + 合成发音」，不是真实录音，TTS 对 `needs-human`、`GOAL-013` 等的读法不一定是你的读法。识别：OpenRouter `qwen/qwen3-asr-1.7b`，**不带任何上下文**（一次）。

## 3. 「当时可得」的词源（严格按时间，不得用未来信息）

| 源 | 构造 | 实体类型 |
|---|---|---|
| **P 项目** | 消息时刻所在项目仓库的快照：取该时刻之前最近一次提交的文件树（`git ls-tree`）：文件基名与去扩展名（type=file）、`tasks/` `goals/` `adr/` 下的名字（task / goal / adr）、`package.json` 的 scripts 与依赖（command / dep）。无法还原时刻的仓库（`cantus` 提交史只有一天）用最早快照并登记 | file / task / goal / adr / command / dep |
| **C 会话** | 同一会话在该消息之前最近 8 个助手回合里的标识符形 token、`tool_use` 的工具名与参数里的路径基名 | tool / file / symbol / term（按形状判型），衰减：回合距离 |
| **U 用户** | 流里**更早**的所有人写消息（含未入选做语音的）里出现过的标识符形 token（「说过 / 发过」）；E3 里再加上被纠正确认过的别名 | term / 其余按形状 |
| 基线 B | 现网：只有 P 里的文件名与裸符号名，经出货 `repairIdentifiers`（编辑距离 + 压扁精确匹配） | — |

**实体资格**（避免把普通英文词当候选）：形状上是标识符，或同时出现在 U / C 中；纯小写单词且在 CMUdict 里的（`index`、`types`）只有出自 U / C 才有资格。

## 4. 候选生成与打分（冻结，沿用 phon.mjs）

窗口 1–4 个英文词；音近度 = CMUdict 音素加权编辑距离 / double-metaphone 骨架（较大者）；`MIN_SIM = 0.75`；`score = 0.45·音近 + 0.25·项目先验 + 0.20·近期 + 0.10·用户历史`，原词作为竞争候选，softmax(T = 0.1)。

- 项目先验 = 1 当且仅当候选 ∈ P ∪ U；近期 = 1 当且仅当候选 ∈ C；用户历史 = min(1, 次数 / 5)。
- **形态类**（窗口与候选只差空格 / 连字符 / 大小写）→ **静默替换**；**其余**（音近类）→ **标记并给候选，不替换**。「标出」= 该窗口有 `p ≥ 0.5` 的非原词候选。
- 为避免对数万个文件名逐个比较：先按骨架首字母与长度 ± 2 分桶，再算音素距离。这是速度优化，不改变定义；若发现分桶漏掉了不分桶时本该有的候选，记为偏差。

## 5. 实验

### E1 标出 + 找到备选（回答 Q1）

对每个**错误的靶 token**（识别文本里该处被写错；位置由金标与识别文本的字符级对齐得到）：

| 读数 | 定义 |
|---|---|
| 标记召回 | 错误处被某个标记窗口覆盖 |
| 备选命中 cand@1 / @3 / @5 | 正确答案在该窗口候选的前 k 位 |
| 全程命中 | 标记 ∧ cand@3 |
| 来源归因 | 正确答案出自 P / C / U 的哪一个或哪几个（可重叠）；**只由某一源独家提供**的比例 |
| 类型分解 | 按实体类型与形态（缩写 / kebab / camel / task 名 / 编号…）分开报 |
| 噪声 | 每 100 字符的标记数；**非错误处**的标记比例；静默替换（形态类）的伤害率（原本对、被改错） |

**消融**：B；P；C；U；P+C；P+U；C+U；P+C+U。每个组合都用同一批识别文本。

**不可达上界**：金标不在任一词源里的错误（真正的新词）单独统计，不计入「找不到」的失败，但要报占比——这是纯词源方案的天花板。

### E2 自动维护机制（回答 Q2）

实体索引的规则（取数前写定，写成可测试的纯函数）：

1. **晋升**：别名（`heard → meant`）首次被纠正 → `pending`；第二次确认或显式「记住」→ `active`。只有 `active` 参与 L1 精确映射。
2. **降级**：`reverts > hits` → 退回 `pending`；90 天（回放里按流内时间折算）未命中 → `archived`。
3. **会话衰减**：C 源条目 8 个回合后失效；同会话再次出现则刷新。
4. **墓碑**：P 源里文件 / 分支在某次快照里消失 → `tombstone`，保留 30 天仍可作候选但打「已删除」标，之后移除。
5. **冲突**：同一个 `heard` 在同一项目对应 ≥ 2 个 canonical → 取左右邻词键区分；没有区分度则都降为 `pending` 并计入「冲突」读数。
6. **反例**：用户把替换撤回成原词 → 记 `{heard, 左邻词}` 为负例，之后同上下文不再标。
7. **规模**：每次只取 top-K（K = 200，按近期、类型、骨架分桶后）进入打分。

测试：确定性断言（每条规则至少一个正例和一个能红的反例），加在真实流上的**不变量**（`archived` 项从不出现在候选；`tombstone` 过期后不出现；`pending` 不触发 L1；候选集大小 ≤ K；同一输入重放两次结果相同）。

### E3 收敛（回答 Q3）

按时间序回放入选消息。每条消息：系统处理识别文本（B 或 P+C+U，加上学到的 L1 别名）→ **理想用户**纠正每一个仍然错的靶 token（成本 = 1 次纠正），并撤回每一个被改错的词 → 系统据此学习（别名 / 负例 / 用户历史计数），**只影响之后的消息**。

臂：

| 臂 | 词源 | 学习 |
|---|---|---|
| A0 | 现网 B | 无 |
| A1 | P+C+U 词源 | 无（只有词源，U 只含「发过」的词） |
| A2 | P+C+U | 纠正后**一次**即晋升 |
| A3 | P+C+U | **两次**确认才晋升 |
| A4 | 仅学习（无 P、C） | 一次晋升 |

指标按 50 条一窗口、滚动：

| 读数 | 定义 |
|---|---|
| **修正负担** | 窗口内仍错的靶 token / 窗口内靶 token 总数 |
| **重复纠正率** | 窗口内仍错、且此前已被纠正过同一 `heard → meant`（规范化后相同）的靶 token 占仍错的比例 |
| **新词占比** | 仍错的靶 token 里「此前从未在任何词源或纠正里出现过」的比例（学习无法消除，词源有机会） |
| 自动修复被还原率 | 系统改过、被理想用户撤回的比例 |
| 收敛判据 | 末三分之一窗口的修正负担 ÷ 首三分之一 |

## 6. 预测（取数前）

| # | 预测 |
|---|---|
| P1 | E1：P+C+U 的**全程命中**显著高于 B；B 对非文件名（task 名、缩写、会话词）几乎为 0 |
| P2 | E1：C 对「刚被助手提到的名字」贡献最大，P 对 task / file，U 对缩写与工具名；三源**各有独家贡献**（独家比例 > 5%） |
| P3 | E1：形态类静默替换的伤害率 ≤ 2%；音近类不静默 |
| P4 | E2：全部断言通过；任意一条规则的反例能让对应断言变红 |
| P5 | E3：A2 的末三分之一 / 首三分之一 ≤ 0.8；A0 ≈ 1.0；A4（只学习）的负担在**新词占比高**时不收敛（高流动词学不过来） |
| P6 | E3：A2 的重复纠正率在前 100 条之后 ≤ 10%；A3 的伤害更低但收敛更慢 |
| P7 | 「新词占比」在末三分之一仍 ≥ 30%：这是词源方案天花板的直接读数 |

## 7. 判定

| 规则 | 通过条件 |
|---|---|
| J1（Q1） | P+C+U 的全程命中 ≥ 0.6，且比 B 高 ≥ 20pp，噪声 ≤ 3 个标记 / 100 字符 |
| J2（Q1） | 形态类静默替换伤害率 ≤ 2% |
| J3（Q2） | E2 断言与不变量全部通过 |
| J4（Q3） | A2 的 末 / 首 ≤ 0.8，**且**重复纠正率（前 100 条后）≤ 10% |
| J5（Q3） | A2 优于 A1 与 A4（学习与词源**互补**：缺一臂都更差） |

结果映射：J1 过 J4 不过 = 标记有用但「越来越准」不成立，要换学习策略；J4 过 J5 不过 = 学习或词源其一多余，可砍；J1/J4 都不过 = 重新讨论方案。

## 8. 局限（取数前登记）

1. **真实文字 + 合成语音。** TTS 对代码样 token 的读法不是你的读法；识别错误形态因此偏离真实口述。**这个实验量的是文本层机制，不是识别器。**
2. **一位用户、四个项目、数月历史。** 不外推到别人。
3. **理想用户**：总能发现并纠正所有错误、不会误纠；真实用户会漏改，收敛会更慢。
4. **项目快照是近似**：分支无法精确还原；`cantus` 历史太短；快照按提交而非按你当时看到的工作区。
5. 打字历史 ≠ 口述内容（口述更长、更啰嗦）；只入选 ≤ 160 字的、含标识符的短消息，会偏高估词表的作用。
6. 音近用 CMUdict + 骨架，没有真 g2p；`cantus` 等词的读音沿用上一轮手写值。
7. 只有一次识别采样；不报识别方差。
8. 原文与识别文本**只落仓库外**（`tc-verify/corpus/voice-index-loop/`）；仓库里只放脚本、规则与聚合读数；入选 / 排除的消息条数在 RESULT 里报告，不含原文。
