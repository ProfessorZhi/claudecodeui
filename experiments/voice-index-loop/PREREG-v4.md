# 预注册 v4：把目标收窄到「有害错误」——误听类的找回、P 词源的真实贡献、以有害错误计的收敛

状态：**新取数（长消息切段的 TTS + 识别、判定器调用）之前提交。** 与 v3 的关系：v3 的读数（`RESULT-v3.md`）已看过，所以 E4、E5 里对**既有 466 条识别文本**的分析**不是盲的**；盲的部分只有 E6 的新音频和 E4 的判定口径。这一点在局限里单独登记。

起因：用户裁定——形态类（`fan in`、`Cloud CLI`、`local storage`）与口语写法类（`AC 零零二`、`provider 下划线 models`）**几乎不影响 Claude Code 的后续处理，属于可容忍错误**。v3 的「找到 43%」、「总负担」把这类也算进去了，掩盖了真正的问题：**误听成别的词 / 对象的错误只找到 9%**。

## 1. 问题

| # | 问题 | 实验 |
|---|---|---|
| Q1 | 「可容忍」的说法是否成立？有害错误占多大比例、分布在哪些形态？ | E4 判定器 + 人工抽样核对 |
| Q2 | 误听类（有害）能找回多少？放宽音近线 + 小模型闭集选择能否把 9% 抬上去，同时不误伤同音陷阱？ | E5 |
| Q3 | 项目词源 P 对**长消息**（文件 / task 名常在其中）到底有没有贡献？ | E6 |
| Q4 | 以**有害错误**计，「越来越准」是否收敛？U 词源的历史导入（冷启动）值多少？ | E7 |

## 2. 定义

**错误**：沿用 v3（靶 token 没有被逐字写进识别文本）。

**可容忍 / 有害**（判定口径，取数前写定）：

1. **规则可容忍**：规范化后（`normKey`）与金标相同（形态类）；或经 `templates.mjs` 的口语模板改写后逐字相同（口语写法类）。
2. **其余错误交给判定器**：判定器看到 ① 金标句 ② 识别句 ③ Claude Code 此刻会有的上下文（该消息此前最近 8 个助手回合里的标识符形 token，至多 60 个，按回合距离排序）。问：*读了识别句，一个编码 agent 能否仍然指向金标里的那个对象？* 答案三选一：`same`（无差别）、`recoverable`（能从上下文无歧义地恢复）、`wrong`（会指错或无法指向）。
3. **有害 = `wrong`**；可容忍 = 规则可容忍 ∪ `same` ∪ `recoverable`。

判定器：`qwen/qwen3.8-27b`（OpenRouter；Anthropic / OpenAI / Google 的模型对本机返回 403，不可用），温度 0。**校准**：另由一个 Claude 子代理对分层抽样的 60 条（规则可容忍 20、`same`/`recoverable` 20、`wrong` 20）做盲评（只看三项输入，不看判定器与分类），报告一致率；**一致率 < 80% 则判定器口径作废，本轮所有「有害」读数降级为「M 类」读数**。

## 3. 实验

### E4 容忍度校准（回答 Q1）

对 v3 的全部 501 个错误 token：规则可容忍的数量与形态分布；其余的判定器三选一分布；与子代理抽样的一致率与分歧样例。读数：**有害错误占全部错误的比例**；有害错误里「可达」（任一词源含正确答案）的比例；按形态分布。

### E5 误听类找回（回答 Q2）

对象 = E4 判定的**有害错误**（次要对象 = v3 的 M 类 240 个）。输入 = v3 已有的 466 条识别文本（+ E6 的新文本，分开报）。词源 PCU 与 v3 相同；**先做 L2a（形态 + 口语模板，静默）**，剩下的才进下面各臂。

| 臂 | 做法 |
|---|---|
| H0 | v3 的 D1（`MIN_SIM = 0.75`），只标记 |
| H1 | 放宽音近线：`MIN_SIM = 0.6`（其余冻结），只标记 |
| H2 | H1 的候选（每窗口取音近度前 K = 15）→ **小模型闭集选择**：给识别句 + 窗口 + 候选编号表（含「保持原样」），只许回一个编号 |
| H3 | 同 H2，另附「会话里最近出现过」标记与词来源标签 |
| H4 | H2 换成参照模型 `qwen/qwen3.8-27b` |

小模型：`mistralai/ministral-3b-2512`、`qwen/qwen-2.5-7b-instruct`（H2、H3 各跑），参照 `qwen/qwen3.8-27b`（H4）。温度 0；闭集选择天然满足「候选必须来自词表」的护栏。解析失败计「保持原样」并单独报告。

读数（每臂）：

| 读数 | 定义 |
|---|---|
| **有害错误找回@1 / @3** | 正确答案是候选里被选中的 / 展示列表前 3 位 |
| **应用后修复率** | 若自动采纳「模型选的非原样候选」，有害错误被修好的比例 |
| **伤害** | 识别本来对的靶 token 被改坏；陷阱句（沿用 `voice-context-asr` 的 8 条 `key` 陷阱 + 6 条中性句，另跑一次 TTS + 识别）被替换的比例 |
| 标记数 / 100 字符、非错误位置的标记占比 | 噪声 |
| 解析失败率、延迟 p50 / p90、成本 | 小模型 |

### E6 长消息切段，P / C 的真实贡献（回答 Q3）

v3 排除了 > 160 字的消息（240 条）与含路径的消息（77 条）。本轮把它们**按句末标点切成 ≤ 160 字的段**（模拟 VAD 切段），保留含标识符形 token 的段；**含路径样式 / 凭据样式的段、与已在 v3 入选的消息重复的段排除**。新段走与 v3 相同的 TTS + Qwen3-ASR 1.7B 流程（运行器、声音与分片规则不变）。

读数：E1 的全套（各词源找到率、来源归因、独家提供比例），并与 v3 并列；**判定 P 是否值得维护**。

### E7 以有害错误计的收敛（回答 Q4）

在 v3 回放引擎上，**口语模板与 L2a 成为基础臂的一部分**（不再是探索变体），所有臂的「负担」改为**有害错误负担** = 判定为有害的错误 token / 靶 token（规则可容忍与判定器可容忍的不计）。

| 臂 | 说明 |
|---|---|
| T1 | PCU 词源 + L2a（含模板），无学习 |
| T2 | T1 + 学习（1 次晋升；别名键用 `heardKey`） |
| T3 | T1 + 学习（2 次晋升） |
| T4 | T2 但 **U 只由语音流自己的消息更新**（不含未入选的人写消息 = 不做历史导入）——量历史导入的价值 |
| T5 | T2 + E5 里最好的找回臂（若通过 J1；否则跳过） |

读数：每 50 条一窗口的有害错误负担；末 / 首三分之一比值；T4 与 T2 在前两个窗口的差（冷启动代价）；重复纠正占剩余有害错误的比例。

## 4. 预测（取数前）

| # | 预测 |
|---|---|
| P1 | E4：规则可容忍的错误里 ≥ 85% 被判定器判为 `same` / `recoverable`（用户的说法成立）；有害错误占全部错误 30–50% |
| P2 | E4：判定器与子代理抽样一致率 ≥ 80% |
| P3 | E5：H1 比 H0 多找回，但标记噪声同比上升；H2 / H3 把有害错误找回@3 从 ~10% 抬到 ≥ 35% |
| P4 | E5：陷阱句上闭集选择因为有「保持原样」而替换率 ≤ 10%，好于 v2 的 D1（86%） |
| P5 | E5：1B–3B 级模型的闭集选择好于 v3 的自由 JSON 输出（解析失败率大降），但 `qwen3.8-27b` 明显更好——差距就是「小模型够不够用」的读数 |
| P6 | E6：P 的贡献在长消息段上明显高于 v3（P 提供的比例 ≥ 10%）；C 的独家比例上升 |
| P7 | E7：有害错误负担的末 / 首比值仍在 0.85–0.9（学习斜率弱的原因没变）；T4 的前两个窗口比 T2 高 ≥ 5pp |

## 5. 判定

| 规则 | 通过条件 |
|---|---|
| J1（Q2） | 存在一臂：有害错误找回@3 ≥ 0.35 且比 H0 高 ≥ 20pp，**伤害（识别本来对的被改坏）≤ 2%，陷阱句替换 ≤ 10%** |
| J2（Q1） | 判定器与子代理抽样一致率 ≥ 80%（否则 E4 / E5 / E7 的「有害」降级为 M 类） |
| J3（Q3） | P 在 E6 里提供的找到比例 ≥ 10% → 保留为一等词源；< 5% → 降为可选 |
| J4（Q4） | T2 的有害错误负担末 / 首 ≤ 0.8；否则登记「斜率不达标，只承诺水平」 |
| J5（Q4） | 历史导入有效：T2 比 T4 在前两个窗口低 ≥ 5pp |

## 6. 局限（取数前登记）

1. **既有 466 条识别文本已被看过**（v3 的失败形态分类、示例形态），E4 / E5 在它们上的结果**不是盲的**；E6 的新音频与判定器调用才是新数据。
2. **判定器是模型**，口径是「一个编码 agent 能否指向金标对象」，它不等于真实的 Claude Code；子代理抽样核对只能给出一致率，不能证明口径本身对。**用户的「可容忍」判断是前提，本轮只检验它是否与判定器一致。**
3. 仍是**真实文字 + 合成语音**；一位用户；理想用户；v3 的所有局限继续有效。
4. E5 的 K = 15、`MIN_SIM = 0.6` 是取数前设的值，只在本轮定一次；调参视为偏差。
5. 候选分桶是否漏候选在 v3 没核对；本轮在 E5 里**补一次核对**（对每个有害错误，不分桶重算一次候选并比较前 3 位），差异计入偏差。
6. 原文、音频、识别文本、判定器输出**只落仓库外**（`tc-verify/corpus/voice-index-loop/`）；仓库里只放脚本、规则与聚合读数。
