# 预注册 v8：SenseVoice 自带标点——`use_itn` 与 `language` 设置对断句的影响

状态：**在任何不同设置下的读数产生之前提交。** 背景：v7 结论是标点保持 SenseVoice 自带，不接标点模型；用户明确**断句是否正确最关键**（空格、连字符、全半角都可以容忍）。本轮只在 sherpa-onnx 暴露的两个设置上找改善：`use_itn`（是否做逆文本规范化，对应模型的 `text_norm` 输入）与 `language`（`auto` 或指定 `zh`）。

## 设计

- 数据：v3 的 466 条（同一批语音、同一份金标 `stream.json` 的键入文本），引擎同 v6（补丁版 sherpa-onnx，CPU）。
- 四个臂：`use_itn ∈ {True, False}` × `language ∈ {auto, zh}`；基线是现网设置 `(True, auto)`。
- 度量（沿用 v7 的空隙口径，只评估对齐匹配处）：
  - **断句 F1**：空隙上「有任何标点（逗号类/句号类/问号类/感叹号类）」与金标是否有标点的 F1；
  - **句末 F1**：句号类/问号类/感叹号类（句子结束）的 F1，含消息末尾空隙；
  - **逗号类 F1**；
  - **字符一致率**：金标去标点字符序列与识别文本的匹配字符占金标字符的比例（防止换设置伤了字）。
- 判定：采纳某个非基线设置当且仅当**断句 F1 与句末 F1 都不低于基线，其中至少一项高 ≥ 0.02，且字符一致率下降 ≤ 0.5pp**。否则保持现网设置。

## 预测（取数前）

| # | 预测 |
|---|---|
| P1 | `use_itn=False` 的标点明显变少（SenseVoice 不做逆文本规范化时标点输出会减弱），断句 F1 低于基线 |
| P2 | `language=zh` 对中英混排消息的拉丁部分有害（字符一致率下降），对断句无显著改善（±0.02） |
| P3 | 没有任何设置同时满足采纳条件 |

## 局限（取数前登记）

1. **语音是 TTS 合成的，不是真实口述。** TTS 会在金标标点处停顿，所以音频里的停顿几乎恰好落在金标标点处——这使「从停顿推断标点」的任务比真实口述容易得多，**绝对数字偏高**；设置之间的相对比较仍有参考意义，但真实说话人（停顿少、停顿处不一定是标点、语速与犹豫）下可能不同。20 条真实录音没有金标，只能作描述。
2. 金标是键入标点（句末常不加句号、逗号少），见 v7。
3. 只测 sherpa-onnx 暴露的两个设置；不改模型、不改补丁。客户端 VAD 的切段（`flushSilenceSec`、最短段）对断句的影响属于另一层，本轮不测。
