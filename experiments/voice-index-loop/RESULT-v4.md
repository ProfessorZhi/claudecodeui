# 结果 v4：以「有害错误」为目标——校准、找回、P 的真实贡献、收敛

按 `PREREG-v4.md`（提交 `0df09b41`，新取数之前）判定。原文、音频、识别文本与判定器输出**只在仓库外**（`tc-verify/corpus/voice-index-loop/`）。**先说局限：E4、E5 用的是 v3 已被看过的 466 条识别文本，不是盲的；盲的只有 E6 的新音频和判定器口径。**

## 一句话

1. **用户的「可容忍」判断成立。** 形态类与口语写法类的 313 个错误里，**98%** 被判定器判为「同一对象 / 可从上下文恢复」。**真正有害的错误只占全部错误的 11%（57 / 501），占全部标识符 token 的 8.5%。**
2. **有害错误的找回，被「候选里有没有」卡死，而不是被「怎么选」卡死。** 即使放宽音近线（0.6）、每窗口取 15 个候选，正确答案也只在 **25%（14 / 57）** 的有害错误的候选里。再好的选择器都不能超过这个上限。
3. **小模型不能直接上。** 闭集选择里，`ministral-3b`、`qwen-2.5-7b` 把**识别本来对的标识符改坏 62–74%**，`API key` 一类陷阱句 100% 被改成 `quay`；`qwen3.8-27b` 明显好（改坏 13%、陷阱 1/7），但也只修好了上限里的那 14 个。**J1 没有一个臂通过。**
4. **项目文件树（P）在长消息里也没有成为主力词源。** 长消息 / 含路径消息切段后，P 提供找到的 7%（独家 1%）。U（你发过的词）仍是最大一源（提供 89%，独家 51%）。
5. **另一个被低估的缺口：中文谐音。** 19 个有害错误被写成纯汉字（`fan-in` →「翻译 / 翻印 / 翻领」，`OOM` →「梦 / 墓」，`e2e` →「一二亿」）。把汉字转拼音、近似成英文音素再匹配（探索，非预注册），**`fan-in` 的 10 个全部排第一**，字母缩写类找不到。加上它，找回上限从 25% 抬到约 42%。

## E4 容忍度校准

| | 数量 | 判定器：同一 / 可恢复 / 有害 |
|---|---|---|
| 规则可容忍（形态 / 口语模板） | 313 | 40% / 58% / **2%（6）** |
| 其余错误（误听等） | 188 | 6% / 66% / **27%（51）** |
| **有害合计（判定器 = wrong）** | **57** | 占全部错误 11% |

判定器 `qwen/qwen3.8-27b`，看到金标句、识别句和该消息此前最近 8 个助手回合里的标识符（至多 60 个）。**盲评核对**：由一个 Claude 子代理对分层抽样的 60 条独立判定，**「可容忍 / 有害」的一致率 51 / 60 = 85%**（规则层 20/20、其余可容忍层 18/20、判定器判有害的一层 13/20——判定器更严，会多判有害）。**三选一的一致率只有 31 / 60（52%）**：判定器爱说 `recoverable`，子代理爱说 `same`——**两者的区分不可靠，只用二分**（J2 通过，限于二分口径）。

有害错误的特征：57 个里 51 个**可达**（U 45、C 37、P 1）；形态：term 37、acronym 12、slug 3、symbol 2、ref 2、env 1；其中**识别结果含拉丁字母 38 个、纯汉字 19 个**。

## E6 长消息切段，P / C 的真实贡献

长消息与含路径消息（v3 排除的 317 条）按句末标点切成 ≤ 160 字的段，保留含标识符的 483 段，**461 段拿到识别文本**，1,125 个靶 token，**904 个识别错（80%）**。

| 词源（PCU，找到的 261 个） | 提供 | 独家 |
|---|---|---|
| U 你发过的词 | **89%** | **51%** |
| C 会话词 | 48% | 6% |
| P 项目文件 / task 名 | **7%** | 1% |

- 找到 29%（形态类 43%，误听类 10%）；**任何词源都够不到的真新词占 38%**（v3 的短消息是 10%）——长消息里新名字多得多。
- 按形态找到：symbol 45%、term 37%、acronym 32%、slug 15%、**ref 5%、env 1%**（这两类被口语写法占据，属可容忍类）。
- **P 的 7% 是在一个有缺陷的快照上测的**：快照取「消息时刻之前最近一次提交」的树，task 文件常在工作树 / 分支里、尚未进入那次提交，所以 slug 类有 52% 判为「不可达」。P 的真实贡献可能略高于 7%，但**不会是主力**。

## E7 以有害错误计的收敛

有害错误还剩多少 / 668 个靶 token（首三分之一 → 末三分之一）：

| 臂 | 剩余有害错误 | 首 → 末 | 比值 |
|---|---|---|---|
| T1 词源 + L2a（无学习） | 53 | 8.2% → 5.6% | 0.69 |
| **T2 + 学习（1 次晋升）** | **41** | 7.2% → 5.1% | 0.70 |
| T3 + 学习（2 次晋升） | 49 | 8.2% → 5.6% | 0.69 |
| T4 = T2 不做历史导入 | 40 | 6.8% → 5.1% | 0.75 |

- **学习少掉 12 个有害错误（53 → 41，约 −23%）**；**但 T1（无学习）自己的首末比值也是 0.69**——斜率主要来自各窗口 token 构成的变化，不能归因于学习。每窗口只有 1–10 个有害错误，**噪声大于信号**。
- **历史导入没有可测的价值**（T2 40–41 对 T4 40 个）：这与「U 提供最多」不矛盾——有害错误里 U 的作用已被「语音流自己的消息」覆盖；历史导入对形态类（可容忍）有价值，对有害类没有。
- T5（E5 最好找回臂 + 学习）没有跑：J1 没有通过。

| 规则 | 读数 | 结论 |
|---|---|---|
| J1 有害错误找回@3 ≥ 0.35 且比 H0 高 ≥ 20pp，改坏 ≤ 2%，陷阱 ≤ 10% | 最好 18%（H1 标出前 3）/ 25%（应用后），改坏 13–74%，陷阱 14–100% | **不通过** |
| J2 判定器与盲评一致率 ≥ 80% | 85%（二分） | 通过（三选一不可靠） |

| J4 T2 末 / 首 ≤ 0.8 | 0.70 | 数字上通过，**但 T1 同为 0.69，不归因于学习，n 极小** |
| J5 历史导入前两窗口 ≥ 5pp | T2 与 T4 几乎相同 | **不通过** |

预测核对：P1 ✓（98%；有害占 11%，低于预测的 30–50%）；P2 ✓；P3 ✗（找回@3 到不了 35%，上限 25%）；P4 部分 ✓（只有 27B 的陷阱替换低）；P5 部分（小模型选对但太爱改，27B 才行）；P6 ✗（P 7%）；P7 ✓（比值 0.7 但不归因）。

## 偏差与局限

1. **E4、E5 不是盲的**（看过 v3 的失败形态）；E6 的 461 段与判定器口径是新的。
2. **判定器是模型**，口径是「一个编码 agent 能否指向金标对象」；三选一不可靠（一致率 52%），只用二分；判定器偏严，有害数偏多。
3. **陷阱句只有 7 + 7 条**（沿用上一轮的 TTS + 识别，没有重做）：陷阱 0 / 7 与 1 / 7 的置信区间都很宽。
4. **J1 的改坏口径**是「识别本来对的靶 token 在系统输出里没有了」，包含系统把它换成别的候选的情形；167 个样本，最大臂差别（13% 对 74%）远大于噪声。
5. **仍是真实文字 + 合成语音**，80% 的靶 token 被识别错（高于真实口述）；一位用户；理想用户。
6. **P 快照有缺陷**（只取已提交的树），E6 的 P 读数是下限。
7. E6 有 22 段（483 → 461）两次重试后仍无识别文本，已排除。
8. 「harmful」里有几个看起来是判定口径的问题（`id` 对 `ID` 被判有害），没有人工逐条复核。

## 对方案的含义（供讨论，未回写提案）

- **有害错误只占约 8.5% 的标识符**，所以「静默修复一切」没有必要；真正的收益点是**让有害的那一小撮不被漏掉**，用下划线 + 候选，而不是追求覆盖率。
- **找回上限的主因是候选召回**。要抬上限，比换更强的选择器有效：中文谐音匹配（+17pp 上限）、更好的音近（真 g2p、字母缩写的读法）。
- **小模型不能自动替换**；如果要用，只能放在「标出后供用户确认」的位置，或者用 27B 级模型 + 严格的保持原样倾向，且需要更多陷阱样本。
- **U 自动入库仍是最大词源；P 降为补充**，不值得单独维护复杂的索引。
- **「越来越准」的承诺**再收窄：对有害错误，学习只带来约 20% 的减少；承诺应落在「说过的词、助手提到的词会稳」，不是「越来越接近完美」。

## 下一轮（建议）

1. **中文谐音 + 字母缩写读法**进入候选召回（预注册后测，在更多词上，不止 `fan-in`）。
2. **用真实录音替换合成语音**：你的 20 条真实录音没有参考文本，但可以用「用户事后纠正」做弱标注——这正是阶段 0 要采的数据。
3. **陷阱样本扩到 ≥ 40 条**，判定「保持原样」倾向的上限。
