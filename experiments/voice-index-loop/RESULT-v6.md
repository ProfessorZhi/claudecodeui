# 结果 v6：统一引擎（打补丁的 sherpa）、候选的来源与类型、规模规则、学习回放、声学别名

按 `PREREG-v6.md`（提交 `dcbe43f1`，第六轮 CTC / 学习 / 别名读数产生之前）判定。原文、音频、识别文本、置信度与逐帧分布**只在仓库外**（`tc-verify/corpus/voice-index-loop/`）。补丁与构建脚本入库：`experiments/voice-index-loop/sherpa-patch/`。

## 一句话

1. **补丁成立，前端问题关闭。** 打了补丁的 sherpa-onnx 1.13.8 给出的文本、token 置信度和逐帧对数概率来自同一个运行时：确定性 150 / 150；与 pip 版的差别只落在不确定的 token 上（置信度 ≥ 0.85 的 token 只有 0.11% 落入差异片段）。自写前端退役。
2. **置信度读数在统一引擎上稳定**：区域级 AUROC，有害错误 **0.93**、全部错误 0.86；θ = 0.6 时 80% 的有害错误落在低置信标记里（只标含拉丁字母 / 数字的段：74%，2.4 个标记 / 100 字符）。
3. **候选的规模规则可行**：每窗口只取 200 个候选，有害错误的候选召回是全量的 92%，CTC 打分耗时降为约六分之一。
4. **声学别名效果最大**：同一个词换一种误听写法再出现时，前 15 位候选召回 **50% → 87%**（n = 30）；全部有害错误前 15 位召回 35% → 54%。**但这里有一个必须先读的限制：合成语音使重复词的声音几乎一样，这个增益很可能被高估**（见局限）。
5. **「学习」本身对有害错误的残留帮助很小**：T2 比 T1 少 12%（67 → 59），没达到预注册的 15%。学习的价值主要在于喂给 CTC 的声学别名，而不是精确替换。

## R4 声学别名（J5：通过，附重要限制）

做法：回放（学习开）在每条消息之前导出「已确认的 `heard → canonical` 别名」，别名的 heard 写法分词后作为该 canonical 的**额外读法**加入 CTC 打分（取各读法的最大似然）。

对象：该词此前已有被确认的别名、但这次的误听写法不同的错误。

| 对象 | 无别名读法 top-1 / 3 / 15 | **有别名读法** top-1 / 3 / 15 |
|---|---|---|
| **有害错误，新写法（n = 30）** | 13% / 33% / 50% | **37% / 63% / 87%** |
| 全部错误，新写法（n = 205） | 40% / 60% / 74% | 47% / 69% / 83% |
| 全部有害错误（n = 69） | 14% / 25% / 35% | 26% / 41% / **54%** |

- **没有挤占正确词**：识别对的靶 token 所在窗口里，排第一的是「仅由别名引入的候选」的次数是 0 / 59。
- **J5（新写法的 top-15 增加 ≥ 10pp）通过**：+37pp。

## 局限

1. **R4 的增益很可能被高估。** 合成语音里同一个词由同一个 TTS 声音反复念出，声音几乎一样，所以「同一个词换一种误听写法」在声学上其实非常接近；真实说话人每次发音有更大的变化，但同一个人对自己的专有名词的发音通常也很稳定，所以方向大概率成立，**大小需要真实录音来确认**。
2. R4 的对象只有 30 个有害错误，置信区间宽；别名来自「理想用户」的确认，真实用户会漏改。
3. R3 的有害错误每窗口只有 1–11 个，噪声大；T2 与 T1 的差距（−12%）不足以下结论。
4. 判定器仍是模型（v4 二分一致率 85%，对新引擎的错误未重做盲评），对有害数有 ±1pp 的波动（patched 版 10.3% 对 pip 版 9.7%）。
5. 仍是**真实文字 + 合成语音**，一位用户。
6. 补丁里的环境变量开关只适合实验；上游化需改成配置项。补丁版是本地编译产物，同一音频在不同编译产物上可能有细微不同的文本（R0）。
7. E6 的 461 段仍只做了前端与速度，没有做判定与候选评估。

## 对方案的含义（供讨论，未回写提案）

- **本地引擎的置信度、候选的来源 / 类型 / 墓碑标记、规模规则**都已经有可用的实现和读数；候选池可以安全地缩到每窗口 200 个。
- **「学习」的主要价值在声学别名**：把用户确认过的「听到的写法」当作该词额外的读法喂给 CTC，同一个词换写法仍能找回；精确的文本替换（L1）对有害错误的帮助很小。这与提案 §5.4 的「别名只做精确映射」不同，要改成「别名同时进入候选打分」。
- **P（项目文件 / task 名）作为候选来源在这批数据上贡献为 0**（仅 P 的找回 0 个），延续 v4 的结论。
- **下一步最需要的仍是真实录音**：R4 的数字必须在真实发音上复核；你的 20 条真实录音是起点，需要事后纠正做弱标注（阶段 0 采集）。
