# 预注册 v5：本地 SenseVoice —— 速度、置信度、CTC 候选打分，与 Omni 并排

状态：**在任何 SenseVoice 与 Omni 的识别读数产生之前提交。** 与前几轮的关系：语料、金标、词源、回放引擎、判定器全部沿用 v3 / v4（`PREREG-v3.md`、`PREREG-v4.md`、`RESULT-v4.md`）；本轮只换**识别器**并加两路新信号。SenseVoice 的前期验证来自另一个会话（`740d5c5a`，2026-10-05）：sherpa-onnx 的 SenseVoice-Small int8，实时因子 0.016，对一段真实录音上低置信 token 落在听错处；自写前端与 sherpa 不逐位一致。

## 1. 问题

| # | 问题 | 实验 |
|---|---|---|
| Q0 | 自写的 CTC 前端 / 解码能否复现 sherpa 的转写（置信度可信的前提）？ | S0 |
| Q1 | 本地 SenseVoice 在**同一批语音**上，逐字与标识符质量、有害错误率、速度，对 Qwen3-ASR 如何？ | S1 |
| Q2 | token 置信度能否把错误（尤其有害错误）排在前面？与候选信号合用能否压掉 54% 的无关标记？ | S2 |
| Q3 | 在低置信窗口上，用词表候选的 **CTC 似然**给候选打分，能否把有害错误的候选召回上限（Qwen3-ASR + 音近：25%）抬起来？ | S3 |
| Q4 | 「SenseVoice + 文本层」对现网 Omni 路径：有害错误残留、延迟、成本，谁更好？ | S4 |

## 2. 数据与引擎

- **语音**：v3 的 466 段（短消息）+ v4 E6 的 461 段（长消息切段）+ 上一轮的 74 段合成句 + 14 条陷阱 / 中性句；金标、靶 token、判定口径不变。**20 条真实录音**只做描述性观察（无金标）。
- **SenseVoice**：`sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17` 的 `model.int8.onnx`，CPU 4 线程，`language=auto`，`use_itn`。
  - **文本**取 sherpa 的转写（引擎事实）；**置信度与逐帧分布**取自写前端 + onnxruntime（前端修正：丢弃输出的前 4 个前缀帧，其余与 sherpa 的特征一致）。
  - S0 把两者并排；**一致率 < 95%（规范化后文本逐字相同）则本轮所有置信度 / CTC 读数标为「前端不一致，仅供方向」**。
- **Omni**：现网 `dashscope-omni` 适配器的请求构造（`buildChatRequestBody`，冻结提示词，无上下文），同一批 466 段，取 `transcript`（逐字）与 `instruction`（书面化）两个字段。
- **Qwen3-ASR**：沿用 v3 / v4 的读数，不重跑。

## 3. 实验

### S0 前端保真
对全部片段：自写贪心解码得到的文本 vs sherpa 文本（去掉 `<|...|>` 标签、空白、标点后逐字比较）的一致率；不一致的类型。

### S1 SenseVoice 对 Qwen3-ASR
- 读数：靶 token 逐字命中率；形态类 / 误听类；经 L2a（形态修复 + 口语模板）后的残留；**有害错误数与率**（沿用 v4 的判定器 `qwen/qwen3.8-27b` 与规则可容忍口径，对 SenseVoice 的新错误重新判定）；识别中文被写成汉字的比例（`翻译` 一类）；速度：每段的解码耗时与实时因子的分布（p50 / p90）。
- 对比对象：Qwen3-ASR（v3 / v4）。

### S2 置信度
- 取每个 token 的 `max softmax`；错误位置 = 靶 token 与识别文本的对齐区域（沿用 `alignRegion` / `widenToWords`，把 token 映射回字符区间）。
- **读数**：(a) 区域级 AUROC：「有错的靶区域的最小 token 置信度」对「识别对的靶区域」；有害错误单独报；(b) 在「每 100 字符至多 N 个标记」预算下（N ∈ {0.5, 1, 2}），低置信度标记对有害错误、对全部错误的召回；(c) 与候选信号合用：D1 标记（沿用 v3 阈值）∩ 低置信、D1 标记 ∪ 低置信，各自的「找到」「无关标记占比」。
- 阈值**不在本轮取数后调参**：θ ∈ {0.5, 0.6, 0.7, 0.8} 全部报告，主读数取 0.6（来自前期会话的观察值）。

### S3 CTC 候选打分
- **窗口** = 连续低置信（`< 0.85`）token 的最大连续段，前后各扩 1 个 token；窗口帧区间由 token 帧位置给出，两端各留 2 帧。
- **候选** = 该消息时刻的全部 PCU 实体（与 v3 回放一致）；分词：对每个词（按 `-`、`_`、驼峰拆开）在 `tokens.txt` 的词表里枚举至多 3 种最少片段的分词，试大小写原样 / 小写 / 大写三种；不可分词的候选跳过。
- **打分**：对窗口帧区间做 CTC 前向（允许两端空白），得到候选序列的对数似然；**假设**同样打分（窗口内的贪心 token）；`LLR = 候选 − 假设`。排序键两种：纯 LLR；`LLR + λ·先验`（先验 = D1 里的项目 / 近期 / 用户历史加权，λ 取使先验与 LLR 数量级相当的固定值，取数前定为 `λ = 1.0`，分数以自然对数计，先验取 `0.25·project + 0.20·recent + 0.10·history` 的原值）。
- **读数**：有害错误（SenseVoice 上的新判定集）与「Qwen3-ASR 判有害的 57 个」的**候选召回**：正确答案在前 1 / 3 / 15；与音近 D1（同一窗口）并排；**在 LLR > 0 的候选里应用 top-1 的伤害率**（识别本来对的靶 token 被改坏）与陷阱句替换率，阈值同样全部报告（LLR ≥ 0、2、4）。
- 局限：`key` 与 `quay` 声学同音，LLR 分不开，只能靠先验；本实验不要求它分开。

### S4 对 Omni
- 同一批 466 段过 Omni：`transcript` 与 `instruction` **分别**按靶 token 命中、有害错误（同一判定器）计；每段耗时（客户端测得）与每音频秒的耗时；用量。
- 并排表：Omni（transcript）/ Omni（instruction）/ Qwen3-ASR + 文本层 / SenseVoice + 文本层；列：靶 token 命中率、**有害错误残留率**、延迟 p50 / p90、成本。**文本层也对 Omni 的 transcript 跑一遍**，以便区分「识别器的差别」与「文本层的差别」。

## 4. 预测（取数前）

| # | 预测 |
|---|---|
| P1 | S0：一致率 ≥ 95%（前期会话里多出的「望」来自未丢前缀帧） |
| P2 | S1：SenseVoice 实时因子 p90 ≤ 0.05；英文标识符的逐字命中率**不高于** Qwen3-ASR（±10pp）；有害错误率与 Qwen3-ASR 同量级（±5pp） |
| P3 | S2：低置信度对有害错误的区域级 AUROC ≥ 0.8；与 D1 标记取交集能把「无关标记占比」降 ≥ 30%，「找到」损失 ≤ 10% |
| P4 | S3：CTC 排序对有害错误的前 15 位召回 ≥ 40%（对照音近 25%）；纯 LLR 对汉字谐音类（`翻译` → `fan-in`）有效 |
| P5 | S4：Omni transcript 的靶 token 命中率与 Qwen3-ASR 相差 ≤ 10pp；Omni 每段耗时 p50 ≥ 0.5 × 音频时长；Omni instruction 的靶 token 命中率**低于** transcript（改写会改写标识符） |
| P6 | S4：SenseVoice + 文本层的有害错误残留 ≤ Omni（transcript 或 instruction）的，且延迟 ≥ 5 倍快 |

## 5. 判定

| 规则 | 通过条件 |
|---|---|
| J1 | S0 一致率 ≥ 95%（否则 S2 / S3 降级为方向性读数） |
| J2 | S2：有害错误区域级 AUROC ≥ 0.8，且在 1 个标记 / 100 字符预算下，对有害错误的召回 ≥ 0.6 |
| J3 | S3：有害错误前 15 位召回 ≥ 40%，且在使「识别对的靶 token 被改坏」≤ 2% 的 LLR 阈值下，应用后修好 ≥ 15% |
| J4 | S4：SenseVoice + 文本层的有害错误残留率 ≤ Omni 的（两个字段都不高于），**且**延迟 p50 ≥ 5 倍快 → 才可以说「更好」；若只有延迟占优、有害错误残留更高 → 只能说「更快」 |

## 6. 局限（取数前登记）

1. 仍是**真实文字 + 合成语音**；Edge TTS 对标识符的读法不是你的读法；识别错误率偏高。**这是对识别器的相对比较，不是对你真实口述的绝对读数**；20 条真实录音只作描述。
2. 自写前端与 sherpa 的不一致（S0 的门）；置信度用 `max softmax`，没有校准，只看排序。
3. 判定器仍是模型（v4 校准：二分一致率 85%），对 SenseVoice / Omni 的新错误没有重做盲评。
4. CTC 分词只是「最少片段」的近似，不等于模型训练时的 BPE 分词；候选里含大写缩写、连字符的，分词质量未知。
5. Omni 一次采样；延迟含网络，随时段波动；用量与价格以服务返回为准，不推算。
6. 陷阱句仍是 7 + 7 条。
7. 原文、音频、识别文本、置信度与逐帧分布**只落仓库外**（`tc-verify/corpus/voice-index-loop/`）。
