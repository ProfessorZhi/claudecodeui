# 预注册 v7：标点后处理——sherpa-onnx 的 CT-Transformer 标点模型能否让 sensevoice-local 的文本更接近书面标准

状态：**在任何标点模型的读数产生之前提交。** 动机：`sensevoice-local` 的标点由 SenseVoice 自己（`use_itn=True`）顺带输出，质量没有量化过；用户希望输出更接近书面标准。方案 A：识别后接一个**只加标点、不改字**的小模型（`sherpa-onnx-punct-ct-transformer-zh-en-vocab272727-2024-04-12`，285 MB，模型文件 `model.onnx`），本轮只测它值不值得接，不改产品代码。

## 1. 数据与引擎

- **金标**：v3 的 `stream.json` 里 `selected` 的 468 条用户真实输入（`text`），带用户自己键入的标点；识别文本取 `sv2/sv.jsonl`（打补丁的 sherpa，v6 的同一份 SenseVoice 输出）。
- **标点模型**：用本机补丁构建里的 `sherpa_onnx.OfflinePunctuation`，CPU，单线程。
- **原文、识别文本与模型输出只落仓库外**（`tc-verify/corpus/voice-index-loop/`），入库的只有脚本与聚合读数。

## 2. 度量

- 把文本去掉空白与标点得到「字符序列」，每个字符后面的位置是一个**空隙**，其标签 ∈ {无, 逗号类（`，、；：` 及半角），句号类（`。` 及半角 `.`，数字与文件名内部的 `.` 不算），问号类，感叹号类}。F1 按类与微平均给出，句末空隙单独报。
- **E1 孤立评测**：输入 = 金标去掉标点、去掉与汉字相邻的空白（模拟识别文本的形状），只测标点模型本身；另报**内容不变率**（输出去掉标点与空白后与输入逐字相同的比例）。
- **E2 流水线评测**：对 SenseVoice 的识别文本，与金标在去标点字符序列上做对齐（`difflib`），**只评估两侧都是连续匹配字符之间的空隙**（识别错误处不评估，评估覆盖率一并报）。三个臂：(a) SenseVoice 自带标点；(b) 去掉自带标点后用模型重加；(c) 自带标点保留，只在自带没有标点的空隙用模型补。
- **E3 标识符安全**：金标里 `ids` 非空的消息，对 E1 的输出检查每个标识符是否原样出现、且内部没有被插入标点；报完整率。
- **E4 速度**：每条消息的模型耗时，中位与 p90。

## 3. 预测（取数前）

| # | 预测 |
|---|---|
| P1 | E1：模型的标点微平均 F1 ≥ 0.60（用户的键入标点本身稀疏、风格不一，上限不会高） |
| P2 | E2：臂 (b) 或 (c) 的微平均 F1 比臂 (a) 高 ≥ 0.05 |
| P3 | 内容不变率 ≥ 99%；标识符完整率 ≥ 97% |
| P4 | 耗时中位 ≤ 20 ms |

## 4. 判定

采纳方案 A 当且仅当：P2 成立（(b) 或 (c) 比 (a) 高 ≥ 0.05）**且**内容不变率 ≥ 99% **且**标识符完整率 ≥ 97%。否则不接，改为只调整现有后处理（例如修正 SenseVoice 自带标点的明显模式）。

## 5. 局限（取数前登记）

1. 金标是用户**键入**的标点，不是口述该有的标点；用户写作时的标点习惯（少用逗号、句末常不加句号）会让「过标点」被算成误报。读数是相对比较（a 对 b 对 c），不是绝对书面质量。
2. E2 只评估对齐匹配处的空隙，识别错误处不评估；覆盖率会低于 100%。
3. 一位用户，468 条里含大量中英混排与标识符。
4. 本轮不评估数字、日期的书面化（逆文本规范化是另一个模块），也不评估大模型改写。
