# E-A2 预注册：用上一轮输出的逐字原文校正识别错误

写于取数之前（2026-10-04）。动机：E-A 发现草稿问题的大头来自识别（`goal` 被截成 `go`、`quay` 听成 `key`、`Cloud Code`），而用户口述里的专有名词（文件名、命令、产品名、英文术语）常常来自刚读完的上一轮输出。上一轮输出是**逐字原文**，可以用来校正这些词。S1 证明了「只输出替换表 + 本地机械校验」在文件清单上有效；A2 证明了「让 omni 带着上下文听」有害。这里测：把**上一轮输出**（而不是文件清单）放在文本阶段，是否有同样的收益。

## 数据

`extract.mjs`：从本项目全部会话里找人类输入，满足：前面有助手输出；自己写的文字（去掉粘贴块与代码块）8–200 字；含至少一个「术语」（拉丁字母 ≥3 位的 token、或数字），且至少一个术语在上一轮输出末尾 8000 字里逐字出现（不区分大小写）。共有 176 条候选，来自 46 个会话。抽样：按种子 `20261007` 洗牌，每个会话最多 3 条，取 60 条。原文只落在仓库外 `tc-verify/corpus/voice-draft-ea2/`。

真值 = 用户当时打的原文。

## 样本

回复原文 → TTS（两个音色按序号交替，`o75` 档）→ omni 无上下文听，E 组两步 JSON，每条 3 次，共 180 次。偏差：打字稿比口述更紧凑；很多术语在口述里本来就不是这样读的。

## 臂（对象 = omni 的整理稿 `instruction`；逐字稿作为证据一并给文本模型）

| 臂 | 做法 |
|---|---|
| N | 不校正 |
| M | 机械词表基线：词表 = 上一轮输出里的拉丁 token；整理稿里不在词表的拉丁 token（≥4 位），若与词表里某词的归一化编辑距离 ≤ 0.3，则替换为最近的词。不调用模型 |
| D-full | `qwen3.8-flash`，上下文 = 上一轮输出（末尾 8000 字），只输出替换表 `{"replacements":[{"from","to"}]}`，本地校验后应用 |
| D-top3 | 同 D-full，但上下文 = 上一轮输出里与口述最相近的 3 个段落（按字二元组 TF-IDF，不调用模型） |
| W | 负控制：D-full，但上下文换成**另一个会话**的上一轮输出（案例 i 用案例 (i+7) mod 60 的，保证会话不同） |

D 的四条校验（任一不满足则丢弃该条替换）：① `from` 是整理稿的子串；② `from`（去掉反引号）不在该上下文里逐字出现（不改已经在上下文里的写法）；③ `to` 在该上下文里逐字出现；④ `from` 与 `to` 去掉非字母数字后的归一化编辑距离 ≤ 0.5。

## 指标（只看整理稿；术语 = 回复原文里的拉丁 token ≥3 位与数字，小写比较）

- **fidelity_in**：回复里「在上一轮输出出现过」的术语，被保留在整理稿里的比例（按术语 × 重复计）。
- **fidelity_out**：回复里「没在上一轮输出出现过」的术语的保留比例（伤害对照）。
- **回退**：N 里保留、校正后丢失的术语数。
- **错换输出率**：校正后的整理稿里，出现了「上一轮输出里有、回复里没有、N 的整理稿里也没有」的拉丁 token 的输出占比。
- **替换精度**：被接受的替换里，`to` ∈ 回复术语且 `from` ∉ 回复术语 的占比。
- 可解析率、延迟。

## 判定（以最好的 D 臂为被测臂，全部满足才算通过）

1. fidelity_in ≥ N + 8pp（绝对值）。
2. fidelity_out ≥ N − 1pp；回退 ≤ 术语总数的 1%。
3. 错换输出率 ≤ 2%。
4. 负控制 W：被接受的替换 ≤ 每 100 条输出 2 个，错换输出率 ≤ 2%。
5. 可解析率 ≥ 95%；延迟 p90 ≤ 6 s。
6. 被测臂 fidelity_in ≥ M + 3pp（否则不需要模型）。

## 人读（强制）

被接受的每一条替换逐条人读（输出 = from → to、真值术语），把机械的「精度」口径与人读不一致处覆盖；报告人读重算后的精度与净收益。

## 已知偏差（取数前登记）

- 真值术语只覆盖拉丁字母与数字；中文词（如「活动坞」）的识别错误不在本实验里。
- 回复里的术语有一部分本来就是通用英文词（task、goal），在上一轮输出里几乎一定出现，容易高估「在上下文里」的比例。
- 60 条、同一用户同一项目。
