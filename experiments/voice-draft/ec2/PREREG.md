# E-C2 预注册：把自我追问编译成「带认知类型的草稿」

写于取数之前（2026-10-04）。起因（用户的区分）：Claude Code 的多轮对话里，后面的问题建立在 Claude Code 刚查到的东西上，是开放的探索；语音草稿**不**应有这么强的外部信息获取能力，只基于口述和最近 2–3 轮已经明确的对话，产出一份让 Claude Code 自己去查的草稿——「带假设和推理的若干问题」。E-C 的失败形态几乎都是话语的**认知类型**丢失（立场变前提、理解问题变修复命令、自问自答的问题被重复提出），所以 E-C2 测的是类型保真，不再是「有没有抓住核心诉求」。

## 认知类型（已与用户确认够用）

事实 / 问题 / 探路 / 假设 / 决定 / 约束。定义见 `gold.json`。系统建议（口述里没有的条件或追问）默认**不写进提示**，放在 `suggestions`，由用户接受后才进入（已与用户确认）。

## 数据

沿用 E-C 的 6 条链、口述脚本与 omni 识别结果（`ec/asr.jsonl`，每单元 × 2 音色 × 3 次，不重新识别）。上下文改为**链前最近 2–3 轮**对话（用户输入 + Claude Code 输出，截尾合计 ≤ 6000 字；EC1 没有，为空）。标准答案 `gold.json` 是逐单元的认知类型，由作者依据口述原文标注，在任何模型调用前提交。

## 臂（`qwen3.8-flash`，`enable_thinking:false`，JSON 输出；一次调用）

| 臂 | 输入 | 上下文 |
|---|---|---|
| A | 逐字稿 + omni 整理稿 | 无 |
| B | 仅逐字稿 | 无 |
| C | 仅逐字稿 | 本链最近 2–3 轮 |
| W | 仅逐字稿 | 另一条链的最近 2–3 轮（负控制：EC1←EC2，EC2←EC3，EC3←EC4，EC4←EC5，EC5←EC6，EC6←EC2） |
| G | 脚本原文（不经 TTS 与 omni） | 无 |

输出：`{"items":[{"type","text","units"}],"self_answered":[{"question","answer"}],"prompt","suggestions":[{"text","why"}]}`。每链 × 音色 × 3 次；G 每链 3 次。

## 度量

机械（全部输出）：
- **类型一致（严格）**：对 `gold.json` 里每个（单元，类型）对，输出里是否存在一条 `items`，其 `units` 含该单元且 `type` 相同。
- **类型一致（宽松）**：把「问题」与「探路」视为同一类（边界本身有主观性）。
- **自问自答识别**：EC1 的（7→8）是否出现在 `self_answered`。
- 建议条数、`items` 引用的单元是否都存在、可解析率、延迟。

盲评（rep 0，每链 × 音色 × 臂，共 6×2×4 + 6(G) = 54 份，乱序，不给臂名）：评审员看口述原文、各单元的标准类型、系统输出，逐条判：
- `hyp`：每个标准「假设」单元，`prompt` 是否把它写成**待检验的假设**且语气强度相当：「忠实」/「削弱」/「变成事实或命令」/「丢失」。
- `ask`：每个标准「问题」单元，`prompt` 是否把它写成**要查明/检查的问题**（而不是命令或陈述）：「是」/「改成命令或陈述」/「丢失」。
- `fact`：每个标准「事实」单元，是否写成「已知」而不是要做的事：「是」/「否」/「丢失」。
- `dc`：每个标准「决定」或「约束」单元是否保留：「是」/「部分」/「丢失」。
- `reask`：被标准判为「自问自答」的问题（EC1 的段 7，EC6 里每条「…要不要…？要，…」的问句部分）是否在 `prompt` 里被重新作为开放请求提出：「是」/「否」。
- `invented`：`prompt` 里口述没说过的要求、事实或条件，逐条列出。
- `sugg_leak`：`suggestions` 里的内容是否出现在 `prompt` 里：「是」/「否」。

## 判定（被测臂 = 在 A、B、C 里机械类型一致最高者；全部满足才算通过）

1. 类型一致（严格）≥ 0.70；（宽松）≥ 0.80。
2. 盲评 `hyp`：忠实 ≥ 0.75；变成事实或命令 ≤ 0.10。
3. 盲评 `ask`：「是」≥ 0.85。
4. 盲评 `fact`：「是」≥ 0.85。
5. 盲评 `dc`：「是」≥ 0.80。
6. `reask` = 「是」≤ 0.15。
7. 编造 ≤ 0.5 条 / 份；`sugg_leak` = 「是」≤ 5%；建议 ≤ 3 条 / 份。
8. 仅逐字稿（B）相对 A：严格类型一致不低于 A − 0.02，`hyp` 忠实不低于 A − 0.05（如果高于则说明阶段②的整理稿有害）。
9. C 相对 B：严格类型一致不低于 B − 0.03，编造不增加超过 0.2；W 相对 B 的类型一致不低于 B − 0.05。
10. 识别误差可吸收：B 的严格类型一致 ≥ G − 0.10。
11. 可解析率 ≥ 95%；p90 延迟 ≤ 20 s。

## 已知偏差（取数前登记）

- 类型标注是作者的，边界（问题 / 探路 / 假设）有主观性，所以同时报宽松口径；评审员是 Claude 系列，被测是 Qwen 系列。
- 6 条链、每臂 12 份盲评、同一用户同一项目。
- 口述是我改写的自问自答；没有真人录音。
- 本轮不做「放进 Claude Code 单轮回答」的端到端验证（已与用户确认第一版先不做）。
