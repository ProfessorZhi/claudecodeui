# E-C 预注册：自我追问 → 核心诉求

写于取数之前（2026-10-04）。动机：未来的语音草稿里，更典型的场景不是一句命令，而是用户读完 Claude Code 的输出后，**对自己连续追问**——自答、试探、转向——最后落到他真正关心的问题或决定上。草稿系统应当找出这条路径，写出一份以核心诉求为中心、不被探路问题带偏的提示。

## 数据：真实链、核心诉求由后续动作推出

- 从本项目会话历史里选 6 条真实的「追问链」（连续 ≥3 条追问/质疑）：EC1 核对依据、EC2 逐步收敛、EC3 原则追问、EC4 条件推进、EC5 前提被推翻前、EC6 决策。链本身与证据包（链前的助手输出、链中每轮、链后 6 小时内**所有会话**的人类输入按时间排列）只在仓库外 `tc-verify/corpus/voice-draft-ec/`。
- **核心诉求的标准答案**是依据链后的后续动作标注的（`gold-v1.json` 为作者版，在看到独立标注之前提交；`gold-v2.json` 加入三位独立标注员的版本，他们只看证据包、不看作者版）。比对结果：EC2–EC6 的核心诉求一致；EC1 视野不同（作者版取紧接着的下一步，独立版取更远的走向），评分取作者版，独立版记为 `far_core`。EC5 的作者版 `core` 取链内的最终询问，更远的转向记为 `far_core`（用户在助手回答之后才转向，口述时不可知）。
- 口述脚本（`scripts.mts`）：把链内用户自己的问题与表态改写成**自问自答**的口述，每条 5–8 个单元，加入犹豫与转折。**只用链内用户自己的话，不含助手的中间回答，也不含链后的任何动作。**
- 每条链还有「链前助手输出」（用户在开口前看到的）作为上下文：EC1 为空（会话开头），EC2 约 2500 字，EC3 约 1000 字，EC4 约 600 字，EC5 约 5100 字，EC6 约 3900 字；本地保存，截尾 6000 字。

## 样本

每个单元用 TTS 念出（`o75` 档），两个音色（`zh-CN-XiaoxiaoNeural` / `zh-CN-YunxiNeural`），各链各音色一套，切段 = 脚本单元（理想切法）。omni 无上下文听，E 组两步 JSON，每个单元 3 次。偏差：改写自打字文本，比真实口述更整齐；链内的助手回答被拿掉，所以核心诉求只能取到「链内最终询问」这一层。

## 臂（文本阶段：`qwen3.8-flash`，`enable_thinking:false`，`response_format: json_object`；输入 = 全部单元的逐字稿与整理稿；一次调用）

| 臂 | 上下文 |
|---|---|
| C0 | 无 |
| C1 | 本链的「链前助手输出」（EC1 为空，等同 C0） |
| CW | 负控制：另一条链的链前助手输出（EC1←EC2，EC2←EC3，EC3←EC4，EC4←EC5，EC5←EC6，EC6←EC2） |
| G0 | 对照：输入是脚本原文（不经 TTS 与 omni），无上下文，每链每次 1 个 |

输出 JSON：`{"core_ask","premises":[],"dropped":[],"prompt"}`。重复：每链 × 音色 × 3 次。

## 度量

- **盲评（主要）**：每链 × 音色 × 臂取 rep 0，共 36 份（+ G0 的 6 份），乱序，评审只看到：口述原文（单元文本）、标准答案（core、must_keep、scaffolding）、系统输出，不知道臂。逐份判：
  - `core`：核心诉求「抓住 / 部分 / 未抓住」（对照标准答案 core；`prompt` 与 `core_ask` 都看，以 `prompt` 为准）。
  - `must_keep`：每条标准前提「满足 / 部分 / 未满足」。
  - `leak`：`prompt` 是否把某条探路问题（scaffolding）当成了独立的要求「是 / 否」。
  - `invented`：`prompt` 里口述没说过的新要求或事实，逐条列出。
- **机械**：JSON 可解析率；`prompt` 长度 / 口述长度（压缩比）；`dropped` 条数；延迟。

## 判定（全部满足才算通过；以最好的上下文臂（C0 或 C1）为被测臂）

1. `core` = 抓住 的比例 ≥ 0.60，且（抓住 + 部分）≥ 0.85。
2. 前提覆盖（满足 + 0.5 × 部分）≥ 0.75。
3. 探路问题泄漏率 ≤ 0.15。
4. 编造 ≤ 0.5 条 / 份。
5. C1 相对 C0：`core` 抓住率下降 ≤ 5pp，编造增加 ≤ 0.2 条 / 份（上下文不能造成害）。
6. CW 相对 C0：`core` 抓住率下降 ≤ 5pp，编造增加 ≤ 0.3 条 / 份（错误上下文下仍稳健）。
7. 识别误差可吸收：ASR 路径 `core` 抓住率 ≥ G0 − 0.10。
8. 可解析率 ≥ 95%，p90 延迟 ≤ 15 s。

## 已知偏差（取数前登记）

- 6 条链、同一用户同一项目；核心诉求由我和三位同属 Claude 系列的标注员推出，不是用户本人的标注。
- 口述是我写的自问自答，保留了用户的问题措辞，但比真实自言自语更有条理。
- 上下文只有链前的一条助手输出；「更早几轮」没有测。
- 评审员是 Claude 系列，被测是 Qwen 系列。
