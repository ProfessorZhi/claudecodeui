# E-A 预注册：引用重建（用户读完上一轮输出后口述回复，系统自动选出他指的那一段原文）

写于取数之前（2026-10-04）。动机：本项目历史里，用户会把上一轮 Claude Code 输出里的一段**手工复制**下来，空一行写 `---`，再写回复（打字时的变通做法）。语音下无法复制，系统应当根据口述，从上一轮输出里**自动选出他指的那一段，逐字附在草稿上**。这是「针对性上下文」最直接、也最容易机械验证的一种用法。

## 数据（真实标签）

`extract.mjs`：从本项目全部会话里找人类输入 = 一段摘录 + 一段回复，且摘录是上一轮助手输出里的一段。规则（在抽取前写定，抽取不涉及任何模型调用）：

- 上下文 = 上一轮助手输出的末尾 8000 字（没有会话超过这个长度）。
- 输入被 `---` 分隔，或按空行分段；恰好一段与上一轮输出逐字重合（12-gram，去掉非字母数字后覆盖率 ≥ 0.8，至少 20 个字符），其余部分与上一轮输出的重合 < 0.5，且自己写的回复 ≥ 4 个字符。
- 摘录在上一轮输出里的字符区间 = 标签。
- 抽取结果 30 对，22 个会话；回复长度中位 30 字（5–99），摘录长度中位 149 字（34–639），上一轮输出中位 3026 字。排除：回复过短 8、无法定位 8。
- 原文与模型输出**只落在仓库外** `tc-verify/corpus/voice-draft-ea/`；仓库里只有选取规则、`cases-index.json`（会话前缀、时间到分钟、各段长度与区间）和聚合结果。

## 样本

- 回复文字用 TTS 念出来：每个案例一个音色，按序号奇偶在 `zh-CN-XiaoxiaoNeural` / `zh-CN-YunxiNeural` 间交替；沿用 `tc-verify` 的 `buildClip`（`o75` 档）。**摘录不念**，作为「待选的上下文」存在于上一轮输出里。
- 偏差：回复是打字的原文，比口述更紧凑；摘录前置的版式意味着用户在打字时已经决定了要引用什么。

## 臂

听：`qwen3.8-omni-flash`，E 组两步 JSON，无上下文，每案例 3 次。选引用与整理草稿：`qwen3.8-flash`，`enable_thinking:false`，`response_format: json_object`。

| 臂 | 做法 |
|---|---|
| B | 词汇基线：把上一轮输出按行切成单元，用字二元组的 TF-IDF 余弦选与口述最相近的 1 个单元（不调用模型） |
| T | 模型选引用，**输入是打字的原文回复**（不经 TTS 与 omni）。分 T-copy / T-ids 两种选法 |
| L-copy | 模型选引用，输入是 omni 的逐字稿与整理稿；要求把原文逐字复制进 `anchor` |
| L-ids | 同上，但上一轮输出按行编号 `[P12]`，模型只返回编号 `anchor_ids`（连续、至多 5 行），由程序取出原文 |
| W | 负控制：L-copy / L-ids 但上下文换成**另一个案例**的上一轮输出（案例 i 用案例 (i+7) mod 30 的；两者不同会话）。此时没有正确的引用，应当返回空 |

草稿字段 `draft`：把用户的回复整理成清楚的一两句话，保持原意，不展开、不补充上一轮的内容，不把引用复述进去。

## 机械指标

位置全部落在上一轮输出的字符区间上；`anchor`（L-copy）先用与抽取同样的链式 12-gram 定位，定位不到即为**非逐字**。

- **逐字率**（L-copy）：`anchor` 可在上一轮输出里定位的比例。L-ids 恒为 100%，另报告 JSON 可解析率。
- **命中率**：`anchor` 区间与标签区间的 IoU ≥ 0.5。同时报告字符级 P / R / F1。
- **空引用率**：`anchor` 为空的比例。
- **污染率**（草稿）：`draft` 含上一轮输出的 ≥ 14 字逐字片段、而回复里没有的比例。
- **术语保真**：回复里的标识符与数字，在 `draft` 里原样保留的比例。
- 延迟（每次调用）与 token。

## 判定（以最好的 L 臂为被测臂，全部满足才算通过）

1. 命中率 ≥ 0.50，且 ≥ 词汇基线 B + 0.10。
2. L-copy 逐字率 ≥ 95%（不满足则只用 L-ids）；JSON 可解析率 ≥ 95%。
3. 负控制 W：被测臂的非空引用率 ≤ 10%。
4. 识别误差可吸收：被测臂命中率 ≥ 对应 T 臂 − 0.10。
5. 草稿污染率 ≤ 5%；术语保真 ≥ 90%。
6. 每次调用延迟 p90 ≤ 10 s。

## 人读（强制）

机械命中可能低估：用户当时选的摘录不是唯一合理的引用。盲评一位独立评审：从被测臂的输出里抽 30 条（含 W），提供回复原文、上一轮输出、系统给出的引用（不给标签、不给臂名），判：引用「恰当 / 部分 / 不恰当」；W 里判「是否应当有引用」。报告机械命中与人读的一致率，以人读重算为准。

## 已知偏差（取数前登记）

- 只有 30 个案例，来自同一位用户、同一个项目；类型偏向「决策类回复」。
- 标签是用户**当时**的选择，不一定是最优引用；用户有时会引用比回复所需更长的一段。
- 回复很短（中位 30 字），指代信息少，这是真实分布，但会拉低命中率的上限。
