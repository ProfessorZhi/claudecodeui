# Voice Draft 预注册：S1（文本阶段消歧）与 S2（长口述 → 增量草稿）

写于取数之前（2026-10-03，基线提交 `02ecb6d2`）。本文件连同 `s2/scripts.mts`（脚本与标准答案）提交之后才开始合成音频、调用模型。判定规则、臂、重复次数不在看过读数之后修改；任何偏离在结果记录里单列。

范围：只用 `qwen3.8-omni-flash`（听）与 `qwen3.8-flash`（文本阶段），均走 DashScope 兼容端点。音频全部由 TTS 合成，不含真人录音。其它模型、真人校准、分段方式比较（S3）、语音命令误触发的专项测试（S4）不在本轮。

## 要回答的问题

A2（`experiments/voice-omni-written/a2/RESULT.md`）证明：把对话上下文交给 omni 模型"带着听"是净伤害。本轮检验替代架构：**omni 只负责听（无上下文），上下文放到随后的文本阶段**。

- S1：文本阶段能否保留上下文的拼写收益，而不引入污染、竞争者替换和编造。
- S2：长口述被切成段、逐段识别之后，文本阶段能否维护一份会撤回、会覆盖、会响应"删掉刚才那段"的草稿。

## S1：文本阶段消歧

**输入**：A2 的 13 条片段（8 条 `d0X` + 5 条 `n0X`）；A2 已有的 `none` 臂输出（`a2/results.jsonl`，取 rep 0–4 各 5 次）作为听的结果，**不重新调用 omni**；A2 冻结的 8 条上下文 `c1…c8`（`fixtures/a2-contexts.json`）。

**臂**（全部以同一份 `none` 输出为输入，因此与 A、B 配对）：

| 臂 | 含义 | 数据 |
|---|---|---|
| A | omni 无上下文（基线） | A2 `none`，已有 |
| B | omni 带上下文 | A2 `c1…c8`，已有 |
| C0 | 文本阶段、**无**上下文（对照：文本阶段自身会不会改坏） | 13 片段 × 5 次 |
| C | 文本阶段带上下文，自由改写整理稿 | 13 × 8 上下文 × 5 次 |
| D | 文本阶段带上下文，只许输出替换表；本地机械校验后才应用 | 13 × 8 × 5 次 |

D 的四条机械校验（任一不满足则丢弃该条替换）：① `from` 必须是整理稿里的原文子串；② `from` 不得本身是仓库已存在的文件名/词干，也不得是上下文里出现过的标识符（不改合法名字）；③ `to` 必须出现在该上下文或仓库名字集里；④ `from` 与 `to` 去掉非字母数字后的编辑距离 / 较长者 ≤ 0.5。

**判定**（C、D 各自对 A 评；B 仅作参照；全部满足才算通过）：

1. **期望净收益为正，两个集合分别算**：与 A2 的 R1 同一公式、同一权重（A1 的 turn1：targetOnly 45.3、targetAndCompetitor 6.7、competitorOnly 4.0、neither 44.0），✅ 判定用 `raw/judge.mts`（旧 8 条）与 `raw/judge-ext.mts`（扩展 5 条），不改动。Δ 取臂 ✅ 率减同批片段在 A 的 ✅ 率。
2. **竞争者上线**：每个分层里，臂的竞争者上线率 ≤ A 在同一批组合上的比率 + 5pp（A2 R2 的口径）。
3. **编造细节 ≤ 2%**：输出里出现上下文中的某个文件名或驼峰名，而它既不在参考文本里、也从未出现在该片段 A 的任何输出里（A2 R3 的口径）。
4. **目标加竞争者分层不退步**：该分层 ✅ 率 ≥ A − 5pp（A2 里 B 在这一格 −28.7pp，是它被否决的主因）。
5. **无标识符片段不受害**：d05–d08、n03、n05 合计 ✅ 率 ≥ A − 5pp。
6. **完整性**：≥ 95% 调用返回 200，且 C 的 JSON 可解析、D 的替换表可解析 ≥ 95%。
7. **延迟只报告**：文本阶段 p50/p90；p90 > 10 s 记为偏差，不单独构成否决。

C0 不参与通过判定；若 C0 相对 A 的 ✅ 率下降 > 3pp，则 C、D 的收益要先扣除这一项再读。

**读数后的强制步骤**（A2 的教训）：机械规则之外，人读 C、D 臂的每一种不同输出，把规则与人读不一致的写成逐条覆盖（`semantic.mts` 的做法），并报告一致率；以人读重算的数字为准。

## S2：长口述 → 增量草稿

**输入**：5 条长脚本 `L1…L5`（`s2/scripts.mts`，每条 11–13 个发言单元，题材取自本项目），每条手写标准答案（应有条目、禁止条目）。单元之间的停顿 2–6 s，单元内部沿用 `o75` 档的块间停顿。两个音色：`zh-CN-XiaoxiaoNeural`、`zh-CN-YunxiNeural`，共 10 段长音频。

**切段**：本轮用**脚本单元边界**切段（理想切法；S3 另测真实 VAD 切法）。每段独立走 `qwen3.8-omni-flash`（E 组，无上下文），每段每音色 3 次，得到逐字稿 + 整理稿。

**草稿阶段臂**（`qwen3.8-flash`）：

| 臂 | 做法 |
|---|---|
| a | 全部段的识别结果一次给出，生成最终 prompt（带上下文胶囊） |
| b | 每段一次增量：模型读"当前草稿条目 + 新段"，只输出操作（add / modify / remove / park / delete_segment / noop）；最终稿由程序把条目按序渲染，不再润色 |
| b0 | 同 b，但**不带**上下文胶囊（隔离上下文的作用） |
| c | 同 b，但把连续的段攒到 ≥ 20 s 语音再更新一次 |
| ga / gb | 同 a / b，但输入是**脚本原文**（不经 TTS 与 omni）——用来分离"识别误差"与"草稿阶段自身的误差" |

上下文胶囊（`s2/capsule.txt`，取数前冻结）：基线提交里与脚本题材相关目录的文件清单（`src/modules/chat/{composer,hooks,transcript}`、`server/modules/voice`、`src/shared`、仓库根的配置文件）+ 分支与提交号。不含任何对话文字。它包含 `VoiceInputButton / VoiceUploadButton / VoiceClipButton`、`useVoiceInput / useVoiceAvailable`、`voice.service / routes / module` 等同族兄弟，是刻意保留的竞争者。

重复：每个（脚本 × 音色 × ASR 重复 r）一次完整的 a/b/b0/c 运行，共 5 × 2 × 3 = 30 次；ga/gb 每（脚本 × r）一次，共 15 次。

**机械指标**（判定器是 `s2/scripts.mts` 里每条标准答案自带的谓词，取数前写定）：

- **召回**：应有条目被最终稿满足的比例。
- **泄漏**：禁止条目（已撤回的、被搁置的、被"删掉刚才那段"删除的、被数字覆盖的旧值）以有效要求的形式出现在最终稿的比例；谓词内含否定语境的豁免。
- **早期存活**：脚本前 1/3 单元引入的应有条目在最终稿中的召回。
- **未知文件名**：最终稿里形如文件名（带已知扩展名）却不在仓库名字集与脚本原文里的串的条数 / 草稿数。
- **操作有效率**（b、b0、c）：JSON 可解析且所有 `id` / `seg` 引用有效的更新占比。
- **每次更新延迟**与 token 用量（b、c）。

**判定**（以 ASR 路径的 b 为被测臂，全部满足才算通过）：

1. 召回 ≥ 0.80，且 ≥ 臂 a 的召回 − 0.05。
2. 泄漏 ≤ 0.10，且 ≤ 臂 a 的泄漏。
3. 早期存活 ≥ 0.85。
4. 操作有效率 ≥ 95%。
5. 每次更新延迟 p90 ≤ 10 s。
6. 上下文不造成害：b 的未知文件名占比 ≤ 2%，且 b 的"标识符召回"≥ b0 的"标识符召回"。
7. 识别误差可吸收：b 的召回 ≥ gb 的召回 − 0.10（否则识别是瓶颈，如实报告，不算草稿阶段的失败）。
8. **命令正确**：L1–L5 里每条"删掉刚才那段"的目标单元，其禁止条目泄漏率 ≤ 0.10；每条含"删掉"字样但属于内容的近似句（L2 第 10 单元、L3 第 11 单元、L5 第 3 单元），其应有条目的召回 ≥ 0.80。

臂 c 与 b 的差异只报告，不设阈值。

**控制**：

- 正控制：ga/gb（无识别误差）应当高于 ASR 路径；若不高于，说明谓词或脚本有问题，先查谓词。
- 负控制（判据自检，取数前跑）：对每条脚本，手工构造一份"含全部禁止条目、缺全部应有条目"的草稿，谓词必须判为召回 0、泄漏 1；再构造一份"逐条照抄标准答案"的草稿，必须召回 1、泄漏 0。任一不满足则谓词作废重写，不得进入取数。

**读数后的强制步骤**：

1. 机械指标与人读的一致率：随机抽 30 份最终稿（ASR 路径各臂均匀），由独立评审（不同模型族）逐条判定应有/禁止/编造，报告与机械判定的一致率与分歧方向；以人读重算的数字为准（A2 的规则系统性低估了伤害）。
2. 按脚本、按音色、按条目类型（新增 / 撤回 / 数字覆盖 / 命令 / 搁置 / 指称）分层报告，不只报聚合。
3. "编造"（草稿里出现标准答案之外的新要求）只靠人读，机械指标不覆盖。

## 已知偏差（取数前登记）

- 音频是 TTS 合成的脚本化口述，没有真人的口误、重复、韵律断裂。结论界定"效应方向与机制"，不是真人上的幅度。
- 单元边界是理想切法，真实 VAD 切法会切断词与跨段更正（S3 另测）。
- 标准答案与谓词由同一人（本实验作者）写成，题材偏向语音与 composer 相关模块；谓词对"同义改写"可能偏严，对"保留原词"可能偏松，故必须人读抽查。
- 评审用的是 Claude 系列模型，被测的是 Qwen 系列，不同族；但评审与作者是同一会话中的模型，抽样与评分标准在读数前写进 `s2/audit.md`。
- 每个（脚本 × 音色 × r）只有 1 次草稿运行，单个格子只说明方向；判定按汇总。
