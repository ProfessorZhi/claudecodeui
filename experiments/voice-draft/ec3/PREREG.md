# E-C3 预注册：一次调用抽取 + 代码渲染

写于取数之前（2026-10-04）。动机：E-A / E-A2 / E-C / E-C2 的上下文结果指向同一个方向——以原文形式交给小模型的上下文，在**自由生成**里会造成污染（E-C2：决定/约束保留 94.4% → 33.3%），在**受限操作**里（逐字引用、替换表加机械校验）才安全有效。E-C2 还暴露三个问题：求证式问句被写成事实、自问自答的问题被重新提出、渲染是模型自由写的。本轮按「合并成一次调用 + 代码渲染」重做：模型不再写提示，只做**抽取**，提示由代码按模板渲染。

## 设计

**一次文本调用（`qwen3.8-flash`，`enable_thinking:false`，JSON）输出三样东西**：

```json
{
  "items":[{"id":1,"unit":4,"type":"假设","span":"逐字稿里的原句","answers":null}],
  "replacements":[{"from":"Go 005","to":"GOAL-005"}],
  "anchors":[{"unit":3,"lines":[12,13]}]
}
```

输入只有**逐字稿**（不看 omni 整理稿，E-C2 里 B ≥ A），加上（部分臂）带行号 `[L1]…` 的链前最近 2–3 轮对话（`contexts2.json`）。

**代码做的事（全部可复现，不调用模型）**：

1. **跨度校验与取原文**：`span` 去掉空白与标点后必须是该段逐字稿的子串；通过的，用逐字稿里对应的**原文片段**替换 `span`（保证逐字）；不通过的丢弃并计数。
2. **类型覆盖规则**：被标成「事实」或「决定」、但原文以问号（？ ?）或「吗」「吧」结尾的话语，强制改标「假设」（求证式问句）。
3. **自问自答合并**：话语 B 的 `answers` 指向更早的话语 A（A 的类型为问题或探路，B 在同一段或之后的段），则 A 不再渲染为请求。
4. **术语校正**（仅在有上下文的臂）：对 `replacements` 逐条校验，全部满足才应用到各条 `span`：① `from` 是该条 `span` 的子串；② `from` 不在上下文里逐字出现（不区分大小写）；③ `to` 在上下文里逐字出现；④ `from` 与 `to` 去掉非字母数字后的归一化编辑距离 ≤ 0.5；⑤（新）`from` 与 `to` 都含拉丁字母；⑥（新）`to` 的路径层级数（`/` 的个数）不得多于 `from`，且 `to` 不含 `*` 而 `from` 含；⑦（新）上下文里与 `from` 的归一化编辑距离 ≤ 0.5 的不同 token 若 ≥ 2 个，放弃。⑤⑥⑦ 是看过 E-A2 的 6 次错误之后加的，**本轮的案例不足以验证，只作为护栏的单元测试和安全检查**（见局限）。
5. **引用**（仅在有上下文的臂）：该段逐字稿含指代标志（那个 / 这个 / 那条 / 这条 / 刚才 / 上面 / 你说的 / 你提到 / 第N个|种|点|条|项 / 方案X）才接受 `anchors`；`lines` 必须连续、≤5 行、在上下文行号范围内；引用文本由代码从上下文按行号取出，逐字。
6. **渲染（模板）**：事实 →「已知：{span}」；问题 →「请检查/查明：{span}」；探路 → 相邻的探路合并成一行「请检查/查明：a；b」；假设 →「我的判断（假设）：{span 去掉结尾问号}，请检验」；决定 →「已决定：{span}」；约束 →「约束：{span}」；引用在对应话语后加「> 引用：…」。提示里**每一句都能追溯到某个段号**。

## 臂

| 臂 | 做法 |
|---|---|
| S0 | 整段口述一次调用，无上下文（只做抽取与渲染，不做校正与引用） |
| S1 | 同 S0，但给最近 2–3 轮，允许校正与引用 |
| W1 | 同 S1，但上下文换成另一条链的（负控制：EC1←EC2，EC2←EC3，EC3←EC4，EC4←EC5，EC5←EC6，EC6←EC2） |
| P1 | 逐段调用（流式形态）：每段一次，给上一段的逐字稿作为回看、已抽取的话语作为状态，带上下文 |
| G0 | 整段一次调用，输入是脚本原文（无识别），无上下文 |

数据同 E-C2：6 条链 × 2 音色 × 3 次（沿用 `ec/asr.jsonl`），G0 每链 3 次。模型的原始输出落盘，代码流水线在分析时重放。

## 度量

机械：
- **跨度有效率**（被丢弃的比例）、**类型一致**（对 `ec2/gold.json`，严格 / 宽松）、**自问自答识别**（EC1 的 7→8）、**覆盖规则触发次数**。
- **术语保真**：真值 = 脚本原文里的拉丁字母 token（≥3 位）与数字；比较「渲染后提示」中保留的比例；同时报告 E-C2 的 B 臂提示（自由生成）与原始逐字稿作为对照。**错换输出率**：提示里出现了上下文里有、真值里没有、逐字稿里也没有的拉丁 token 的输出占比。
- 接受的替换条数、接受的引用条数（W1 里应为 0）、调用次数、每次调用延迟、提示长度。

盲评（沿用 E-C2 的评审量表，rep 0 每链 × 音色 × 臂，共 6×2×4 + 6 = 54 份；乱序，不给臂名）：`hyp`、`ask`、`fact`、`dc`、`reask`、`invented`；再加 `read`：提示作为给 Claude Code 的一段文字，可读性「好 / 可接受 / 差」。

## 判定（被测臂 = S0、S1、P1 里机械严格类型一致最高者；全部满足才算通过）

1. 严格类型一致 ≥ 0.70；宽松 ≥ 0.80。
2. 盲评 `hyp`：忠实 ≥ 0.75，变成事实或命令 ≤ 0.10。
3. 盲评 `ask` 「是」≥ 0.85；`fact` 「是」≥ 0.85；`dc` 「是」≥ 0.80。
4. `reask` 「是」≤ 0.15。
5. 编造 ≤ 0.3 条 / 份。
6. 上下文安全：S1 相对 S0 的 `dc` 保留不低 3pp、编造不增超过 0.2；W1 相对 S0 同；W1 的接受替换 ≤ 每 100 条输出 2 个，W1 的接受引用 ≤ 每 100 条输出 2 个。
7. 术语保真：S1 ≥ S0 + 3pp；错换输出率 ≤ 2%。
8. 可读性：「好」+「可接受」≥ 0.80。
9. P1（流式）严格类型一致不低于 S1 − 0.05。
10. 跨度有效率 ≥ 0.90；可解析 ≥ 95%；P1 每次调用 p90 ≤ 8 s。
11. 相对 E-C2 的 B 臂（自由生成）：`hyp` 忠实与 `reask` 至少各改善 10pp（报告，不设门槛）。

## 已知偏差（取数前登记）

- 6 条链、每臂 12 份盲评、同一用户同一项目；评审员是 Claude 系列，被测是 Qwen 系列。
- 术语校正的新护栏（⑤⑥⑦）是看过 E-A2 的错误后加的，本轮案例里几乎没有可校正的术语，**不能验证它们**；需要一批新案例（E-A3）。
- 引用的收益本轮也难以体现：6 条链里几乎没有指代上一轮输出的口述。
- 渲染是模板的，读起来较机械，可读性由盲评判断。
- 没有做「放进 Claude Code 单轮回答」的端到端验证。
- 本轮不生成「系统建议」（`suggestions`）：它在 E-C2 里已被证明可以隔离。
