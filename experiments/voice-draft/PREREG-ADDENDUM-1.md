# 预注册补充 1：S2 增量草稿改为「整份草稿重写」

写于重跑之前（2026-10-03）。起因：S2 结果（`RESULT.md`）里增量操作表的主要失败（「保持原样」类决定被输出成 `noop`；条目文字被合并后无法按段删除）出在**让模型做机械的操作分类**上。用户指出的方向：草稿通常不长（极少超过千字），应当把**当前草稿全文**交给模型，让它像助理一样根据新的语音输入更新或修改草稿，可参考其它上下文，而不是让它输出操作。

## 这一轮的偏离，先说清楚

- **提示词是在看过 S2 失败原因之后写的。** 新提示词里明确写了「说话人表示先不改 / 保持原样 / 不用写进某处 / 留着当兜底时，要写成一条明确的约束」，这正是 S2 诊断出的缺口。因此新臂与旧 b 的比较**不是盲的**；为公平起见，一次整理也用同一份规则重跑一次（臂 a2）。
- 评审沿用 S2 的盲评规程，但**只审新臂**；旧臂 a/b/b0/c 的人读数沿用 `RESULT.md`。

## 臂（识别结果沿用 S2 的 `asr.jsonl`，不重新识别；同样 30 个 ASR 路径 run + 15 个脚本原文 run）

| 臂 | 做法 |
|---|---|
| r | 每段一次：输入 = 当前草稿全文 + 上一版草稿全文 + 最近 3 段的原话 + 新段（逐字稿 + 整理稿）+ 项目文件清单；输出 = **更新后的整份草稿**（纯文本，条目式）。草稿末尾可有一节「【暂存】」放被搁置的想法，评分时去掉这一节 |
| r0 | 同 r，但不给项目文件清单（隔离上下文） |
| a2 | 一次整理，用与 r 相同的规则文字（对照；旧 a 用的是 S2 的规则） |
| gr | 同 r，输入是脚本原文（不经 TTS 与 omni） |

模型与参数同 S2：`qwen3.8-flash`，`enable_thinking:false`，服务默认温度。语音命令「删掉刚才那段」「撤销」由模型根据「上一版草稿」和「最近 3 段」处理，不再由程序按来源段删除；这也意味着**中间某一段的删除**需要模型自己判断，S2 的脚本里没有这种情形，本轮不测。

## 判定

沿用 `PREREG.md` 的 S2 判定 1–8，被测臂换成 r，基线「a」换成 a2，「b0」换成 r0，「gb」换成 gr。没有「操作有效率」（规则 4 作废，改为：输出非空且不含解释性前缀的更新占比 ≥ 95%）。机械指标沿用 `s2/scripts.mts` 的谓词（含 S2 之后的缺陷修复），评分前去掉「【暂存】」一节。

人读审计：从 r、r0、a2 的 ASR 路径最终稿中抽 30 份（r 12、r0 9、a2 9；每脚本 6 份；种子 `20261004`），盲评、顺序打乱，规程同 `s2/audit.md`，评审用 `required_item_ids` 约束键。

**读数后的强制步骤**：与 S2 相同；另外单列「相对 S2 的 b / a 的变化」，并如实说明这是在知道失败原因之后改的提示词。

## 已知风险（取数前登记）

- 整份重写可能漂移：早期约束在多次更新后被改写或丢掉（`早期存活` 指标会暴露）。
- 每次更新输入变长（草稿 + 上一版 + 3 段），延迟与 token 比操作表高；要报告。
- 「【暂存】」一节的存在可能让模型把本该丢弃的内容也保留下来，评分去掉该节后，这类内容不影响泄漏指标，但会影响「用户看到的草稿」；人读时一并看全文。
