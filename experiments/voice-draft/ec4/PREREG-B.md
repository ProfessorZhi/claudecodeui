# E-C4b 预注册：v3 修法在第二批新案例上的验证

写于取数之前（2026-10-04）。

## 背景

E-C4 在 EH1–EH4 上验证了 v2（保留「问 + 答」）：提示能独立读懂决定的比例从 6.3% 升到 81.3%，可读性「差」从 87.5% 降到 0%；但 `reask` 没有改善（23.3% 对 v1 的 16.7%），且 EH4 的保留只有 60%。评测之后查出两处**代码缺陷**（不是规则本身的问题）：

1. **单字回答被当作无效跨度丢弃**：「改。」「写。」，以及被模型拆出来的「行」，因为跨度校验要求至少 2 个字符。
2. **无问号的问句不被认作问句**：转写里的停顿常把问号标成逗号（「要不要先改成按需加载，应该要，……」），于是整组配对没有形成。

## v3（只改代码，`ec3/pipeline.mts` 的 `runV3`；v1、v2 的行为不变）

- 单字跨度只在它是**整句/整个分句**时才算逐字（句中的单字如「他说行，但……」不接受）。
- `isQuestion` 在 v3 里放宽：含「要不要 / 是不是 / 能不能 / 行不行 / 对不对 / 会不会 / 有没有」，或以「吗」结尾，即使没有问号，也算问句形态。
- 其余同 v2（配对护栏、渲染格式）。

EH1–EH4 已经因为发现缺陷而**不再是 hold-out**，不再用来证明 v3。

## 验证：第二批新案例

`scripts-b.mts`：EH5–EH8，4 条链、19 个单元（极短回答、选择与理由、假设与未决混合、长短回答混合），措辞与 EH1–EH4 不同。流程同 E-C4：TTS（两个音色）→ omni 无上下文听（每单元 3 次）→ E-C3 的抽取提示词（整段一次调用，无上下文，原样）→ **同一份原始输出分别用 v1、v2、v3 渲染**；另有 G 臂（脚本原文）。

盲评（rep 0；4 条链 × 3 路径（两个音色 + G）× 3 个版本 = 36 份；乱序，不给版本名）：量表同 E-C4（`ret`、`reask`、`mis`、`read`、`invented`）。

## 判定（被测版本 = v3；ASR 路径与 G 合并计）

1. `ret` 「是」≥ 0.85，且 ≥ v1 + 0.20，且 ≥ v2。
2. `reask` 「是」≤ 0.10，且 ≤ v1。
3. 错配对数 ≤ 所有配对的 10%。
4. 可读性（好 + 可接受）≥ 0.80，「差」的占比不高于 v1。
5. 编造 ≤ 0.3 条 / 份，且不高于 v1。
6. （机械）已回答的问句被配对的比例 ≥ 0.80；v3 的配对在非预期段（既不是已回答的问句，也不是 EH7 段 4）为 0 或解释清楚。

## 已知偏差（取数前登记）

- 4 条链、19 个单元，同一作者写脚本；回答偏短，难度偏低；EH5/EH8 的极短回答正是 v3 要修的形态，所以这批对 v3 有利。
- v3 的两处放宽可能增加误配（「他说行」、含「是不是」的陈述），本批只有少量这类句子。
- 评审员是 Claude 系列，被测是 Qwen 系列。
