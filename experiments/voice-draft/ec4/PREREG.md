# E-C4 预注册：修「省略的回答」

写于取数之前（2026-10-04）。动机（E-C3 的发现）：EC6 的口述是「密钥要不要留在 config_json 里？要留，可用性比保护更重要」。抽取出问句和回答两个逐字跨度，自问自答合并去掉了问句，渲染成「已决定：要留，可用性比保护更重要」，**主语丢了**（决定/约束保留 66.7%，EC6 只有 38.9%）。逐字复制无法把问和答合成一句陈述。

## 修法（只改代码，不调用额外的模型；`ec3/pipeline.mts` 的 `pairAnswers` / `renderV2` / `runV2`，v1 不变）

1. **配对**：把「问句 + 回答」配成一对。来源有二：① 模型给的 `answers`，但要过护栏：问题必须是问句形态（以问号结尾，或含「要不要 / 是不是 / 能不能 / 行不行 / 对不对 / 会不会 / 还是 / 吗」并带问号）；回答必须是决定 / 约束 / 事实 / 假设且**本身不是问句**；回答至多在问句之后一段；② 规则：同一段内、问句后紧跟的决定 / 事实 / 约束 / 假设，且去掉口头禅后以应答词开头（要 / 不要 / 不用 / 不 / 是 / 对 / 行 / 好 / 可以 / 应该 / 先不 / 留 / 带 / 改 / 记 / 沿用 / 保持 / 照旧 / 按 / 都 / 有 / 没有 / 右边 / 左边）或不超过 8 个字。
2. **渲染**：配对后不再丢掉问句，而是**两者逐字保留**：`已决定：（问）{问句}（答）{回答}`；回答是假设时 `我的判断（假设）：（问）…（答）…，请检验`；约束 `约束：（问）…（答）…`；事实 `已知：（问）…（答）…`。未配对的问句仍是「请检查/查明」。

护栏和应答词表是看着 E-C3 的 EC 数据（EC2、EC4、EC5 的误配，EC6 的正确配对）定的，所以 EC 数据上的任何结果都是样本内的，**不能作为证据**。

## 验证：新案例（hold-out）

`scripts.mts`：4 条与 EC 链无关的口述 EH1–EH4（句内问答、跨段回答与选择、问答混着假设与未决、极短回答），共 19 个口述单元；每段落的「必须能独立读懂的内容」（被决定的对象 + 方向）和「说话人自己回答了的问句」在 `scripts.mts` 里写定。TTS（两个音色，`o75` 档）→ omni 无上下文听（E 组两步 JSON，每单元 3 次）→ E-C3 的抽取提示词（整段一次调用，无上下文，原样）→ 同一份原始输出分别用 v1 和 v2 渲染（**抽取相同，只有渲染不同**，所以是干净的 A/B）。另有 G 臂：脚本原文输入。

盲评（rep 0，每条链 × 音色 × 版本，共 4×2×2 = 16 份，加 G 的 4×2 = 8 份；乱序，不给版本名）：评审员看口述原文、每段的「必须读懂的内容」、系统输出，逐段判：
- `ret`：该内容是否在提示里**连同被决定的对象和方向**，不看口述也能读懂：「是」/「部分」（方向有但对象不清）/「丢失」。
- `reask`：对说话人已回答的问句，提示是否又把它当作开放请求提出：「是」/「否」。
- `mis`：提示里每一个「（问）…（答）…」对，回答是否真的回答了该问句：逐对列出「错配」的（没有就空）。
- `read`：整段提示的可读性「好 / 可接受 / 差」。
- `invented`：口述没说过的内容。

## 判定

1. v2 的 `ret` = 「是」≥ 0.85，且 ≥ v1 + 0.20。
2. v2 的 `reask` = 「是」≤ 0.10，且 ≤ v1。
3. v2 的错配对数 ≤ 所有配对的 10%。
4. v2 的可读性（好 + 可接受）≥ 0.80，且「差」的占比不高于 v1。
5. 编造 ≤ 0.3 条 / 份；v2 不增加编造。
6. （机械）新案例中，v2 对「说话人已回答的问句」的配对覆盖率（问句与回答被配成一对的比例）≥ 0.80；未决问句（EH3 的段 3）不应被配对。

## 已知偏差（取数前登记）

- 4 条链、19 个单元、同一作者写脚本；回答多是短句，和我设计规则时看到的形态相近，难度偏低。
- 评审员是 Claude 系列，被测是 Qwen 系列。
- 「他/这个/那个」这类指代省略（EC6 里的「已决定：这个我能接受」）不是本修法要解决的问题，本轮不处理。
