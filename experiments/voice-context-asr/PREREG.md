# 上下文 ASR 预注册：同音标识符（`key` ↔ `quay`）能否在解码阶段由上下文消歧

状态：**已被 `PREREG-v2.md` 取代（上下文送入 ASR 这条线已被 A2 否决，试点已停）。** 原状态：设计稿，未取数。 取数之前提交；提交之后改判据 = 登记为偏差，不得静默改。

关系：

- 动机来自 `docs/proposals/voice-correction-feedback-loop.md` §5.1 的 L1–L3，与「ASR 解码阶段知道 `quay` 是高概率词」这条路线的讨论。
- 本实验**不重做**已有读数，只在它们之上补缺口：
  - `docs/experiments/2026-09-23-webm-asr-candidates.md` §五：`qwen-audio-3.1-asr-flash` 经 system 消息「context honored」，OpenRouter 的 `qwen3-asr-flash` 经出货适配器「not honored」（适配器 `honors.context:false`，请求里根本没带）。
  - `experiments/voice-omni-written/raw/e-ctx*.jsonl`：omni 吃 4 个真名 / 70 名 / 全量 2447 名 / 一条真实助手回复。结论摘要（`docs/proposals/voice-dashscope-omni-written-instruction.md`）：**热词只在词表「极短且全对」时有效，给真实项目词表会误插。**
  - `experiments/voice-draft/RESULT.md` S1：带上下文的自由改写会伤人，替换表 + 机械校验可行。
- 缺口（本实验要回答的）：**那些实验的靶词没有「真同音」的难例，也没有「真词恰好是同音词」的陷阱句，所以量不出误插代价与真消歧收益之间的交换。**

## 1. 问题与假设

| # | 假设 | 若成立 | 若不成立 |
|---|---|---|---|
| H1 | 对**声学上同音**的项目词（`quay`/`key`），给 ASR 一段短而正确的上下文，能显著提高命中 | 上下文 ASR 值得进入适配器（提案阶段 4 提前） | 解码阶段偏置对同音词无效，只剩识别后重打分 |
| H2 | 上下文越长越杂，误插越多（全量词表 > 短词表 > 真实助手回复，在陷阱句上递增） | 词源要**裁剪**后再喂，不能把 2447 个名字全塞 | 可以放心喂全量，省掉裁剪 |
| H3 | 命中的提升**来自靶词本身**，而不是「任何上下文」 | 机制成立 | 提升是 prompt 的副作用，结论作废 |
| H4 | 识别后「音近 × 项目先验 × 最近出现 × 用户历史」重打分，在同音类上优于现网的编辑距离修复 | 提案的 L2 要加音近键 | 编辑距离已够用，不引入音素表 |
| H5 | 两层叠加（上下文 ASR + 重打分）优于任一单层 | 保留两道防线 | 只留较简单的那一层 |
| H6 | 有分数的路径（引擎自带 / 重打分）能把「可能听错的词」排在前面，足以驱动 UI 虚线下划线 | 用分数标记 | 用规则标记（标识符形且未命中）即可 |

## 2. 语料（取数前冻结）

### 2.1 靶词表（40 个，全部来自本机真实历史）

按声学风险分四类，**类别在取数前按人读写定，不由模型输出决定**：

| 类 | 说明 | 示例（最终名单在 `terms.json`，随语料冻结） | 个数 |
|---|---|---|---|
| A 同音歧义 | 存在同音的常见英文词 | `quay`/key、`quay-fleet`/key fleet、`cantus`、`archguard`（arch guard）、`needs-human` 等 | ≥ 10 |
| B 切分 / 形态 | 一个符号被听成多个词 | `CloudCLI`/cloud CLI、`SendMessage`、`fan-in`、`meta-cc`、`worktree` | ≥ 12 |
| C 字母缩写 | 逐字母念 | `MCP`、`PWA`、`VAD`、`OOM`、`E2E` | ≥ 8 |
| D 编号 | 模板 + 数字 | `GOAL-013`、`AC-103`、`ADR-004` | ≥ 6 |

频次来源：`/tmp/vk` 的历史统计（`quay` 358、`needs-human` 103、`CloudCLI` 88、`fan-in` 46、`SendMessage` 44……）。靶词按「出现次数分层」抽，不只挑头部：**一半取头部 20、一半取尾部（出现 ≤ 3 次）**，用来测「用户历史先验用不上时」的冷启动。

### 2.2 句子

每个靶词 3 个模板，模板**由真实历史消息改写**（把靶词位置抽成槽），三种语言形态各一：

- 中文主句 + 英文靶词（「创建一个 {T} 任务。」）
- 纯英文指令（"Create a {T} task."）
- 靶词在句中、前后都是中文（「用 {T} 检查一下会话。」）

共 120 条**靶句**。另有：

| 集 | 数量 | 作用 |
|---|---|---|
| **陷阱句** | 60 | 说的**就是**那个同音普通词，上下文里却有项目词。例：「`key file` 已更新」（真实历史里有原句）、"press the key"、"the API key is rotated"、"the quay at the harbour"。**正确答案是不要替换。** |
| **中性句** | 30 | 无任何靶词，也无同音词。用来数「凭空插入」 |
| **多靶句** | 20 | 一句里 3–5 个靶词，中英混杂（模拟中位 4 次切换） |

合计 230 条。**按模板切分开发 / 测试：30% 模板（含其全部靶词变体）进 dev，只用来定阈值；70% 进 test，冻结后只读一次。** 靶词表也切：每类留一半靶词只出现在 test，用来量「没见过的词」。

### 2.3 音频

两档，**两档读数分开报，不合并**：

| 档 | 来源 | 为什么 |
|---|---|---|
| T（合成） | 2 个中文 + 2 个英文音色（沿用 `tc-verify` 的 `buildClip` 与 `o75` 档），靶词发音取**两种**：词典读音 与 强制 /kiː/ 变体（SSML / 音素覆盖） | 可重复、可放大 n。**风险：TTS 把 `quay` 念成 /kweɪ/ 就根本没有同音问题**，所以必须有强制 /kiː/ 变体，并在报告里列出每个 TTS 实际读音（用一个与靶词无关的识别器听写校验） |
| **R（真人）** | 用户本人按同一脚本朗读，至少 **A 类全部靶句 + 陷阱句 + 多靶句**（约 90 条，约 10 分钟）；用现网麦克风与 webm/opus 上传链路录 | **整个实验最关键的一档**：用户到底把 `quay` 读成 /kiː/ 还是 /kweɪ/、中文句里英文词的口音，只有真人能给。T 档的任何结论都不能替代 R 档 |

原始音频、转写正文**只落仓库外** `tc-verify/corpus/voice-context-asr/`；仓库里只放脚本、`terms.json`、`cases-index.json`、聚合读数（沿用本仓库既有约定）。

## 3. 臂

### 3.1 引擎（先过 §6 的探针门，不过的引擎不进主实验）

| 引擎 | 怎么接 | 支持上下文？ |
|---|---|---|
| E0 | 现网：DashScope `qwen3.8-omni-flash`，出货适配器 | 适配器 `honors.context:false`；作基线 |
| E1 | Groq `whisper-large-v3-turbo`，出货适配器 | `honors.prompt:false`；作基线 |
| E2 | DashScope `qwen-audio-3.1-asr-flash`，runner-local wire（沿用 2026-09-23 记录的 wire） | system 消息（已测「honored」） |
| E3 | **Qwen3-ASR 0.6B**，本机 CPU | 官方推理接口的 `context` 参数（**待探针证实**，见 §6） |
| E4 | **Qwen3-ASR 1.7B**，本机 CPU | 同上 |
| E5 | SeACo-Paraformer（FunASR），`hotword` | 解码器热词（**中文偏重，英文标识符表现是未知数**） |
| E6 | sherpa-onnx transducer + hotwords | 仅当找到中英双语模型；否则**不进本轮**，登记原因 |

SenseVoice 不进本轮：没有通用 decoder 热词输入，只作为「无上下文的低延迟参照」若需要再加。

### 3.2 上下文条件（只对 E2–E5 有意义；E0/E1 只跑 C0）

| 条件 | 内容 | 预测 |
|---|---|---|
| C0 | 无 | 基线 |
| C1 | **短而全对**：项目名 + 5–6 个近期项目词（含该句靶词） | A 类命中↑ |
| C2 | **真实助手回复**（冻结的 `fixtures/real-ctx.json` 同款，2k–8k 字符，含靶词于自然语句中） | 介于 C0 与 C1 之间，误插低于 C3 |
| C3 | **全量项目名**（≈2.4k 个） | 命中不再增、陷阱 / 中性句误插↑（既有读数的复核） |
| C4 | **错项目上下文**（换成另一项目的词：archguard / cantus / meta-cc 的 5–6 词） | 命中 ≈ C0；不应把 `key` 变成 `quay` |
| **C5（能红的负对照）** | 与 C1 **逐字相同，只把靶词本身从上下文里删掉**（长度、格式、其余词都不变） | 命中 ≈ C0。若 C5 的命中接近 C1，说明收益来自「任何上下文」而非靶词 → **H3 证伪，整条路线的读数作废** |

C5 先于其余条件写定其预测；每个引擎都必须跑 C0、C1、C5，缺一个该引擎不进结论。

### 3.3 识别后重打分（对每个引擎的输出各跑一遍）

| 条件 | 内容 |
|---|---|
| R0 | 不处理 |
| R1 | 出货 `src/shared/identifierRepair.ts`（候选 = 文件名，现网同口径） |
| R2 | **被测**：候选 = 靶词词源并集（项目词表 + 会话词 + 用户历史）；对 ASR 输出中每个 token / 相邻 token 序列，用 `score = 0.45·音近 + 0.25·项目先验 + 0.20·近期 + 0.10·用户历史` 选候选；低于阈值不替换。**权重在取数前定死，阈值只在 dev 上定**（扫描范围与步长在此登记：阈值 0.5–0.9，步长 0.05） |
| R3 | R2 去掉三个先验项，**只留音近** | 
| R4 | R2 去掉音近项，**只留先验**（会把一切都往 `quay` 拉，应在陷阱句上暴露） |

音近键：英文用 CMUdict / g2p 的音素序列（去重音、合并相近元音）；中文转写体（「克伊」「凯」）用拼音近似，**仅在 R 档出现这类输出时才补，补了就登记为偏差**。音素表是新的外部依赖，许可证与体积在探针门里核实。

R2 的实现必须放在可被出货代码 import 的位置（`src/shared/` 下新文件），实验工装只 import 它，**不在工装里放第二份算法**（`docs/experiments/README.md` 协议第 3 条）。

## 4. 指标

全部**逐字、大小写敏感**，口径用出货 `src/shared/identifierFidelity.ts`；同时报告宽松口径，两者**并列不合并**（README 的口径分歧表）。

| 指标 | 定义 | 分母 |
|---|---|---|
| **IER**（Identifier Error Rate） | 靶词没有被逐字写对的比例 | 靶句 + 多靶句里的靶词出现次数 |
| **AIR**（Ambiguous Identifier Recall） | A 类靶词写对的比例（= 1 − A 类 IER） | A 类出现次数 |
| **FIR**（False Injection Rate） | 陷阱句里，该是同音普通词却被写成项目词的比例 | 陷阱句 |
| **插入数** | 中性句里凭空出现项目词的个数 / 句 | 中性句 |
| **净收益** | 命中数 − 误伤数（误伤 = 原本对、被改错：陷阱句误替换 + 靶句里别的 token 被改坏） | 同一配对集 |
| CER / WER | 数字写法归一后，沿用 2026-09-23 口径；仅作辅助，**不作判据**（它对标识符失明） | 全集 |
| 延迟 p50 / p90、成本、本机 RTF | 引擎自报 / 计时 | 每引擎 |
| 标记质量（回答 H6） | 在固定「标记预算」下（≤ 10% 的 token 被标记），被标记集合覆盖多少真错误：recall@10% 与精确率；有分数的路径另报 AUROC | 全集 |

指标自测：在写好的 12 个已知答案用例上先跑（含中文句、含大小写错、含「key file」陷阱、含一句多靶词），自测不过不取数。负对照：把所有输出替换为参考文本应得 IER = 0、FIR = 0；把所有靶词替换为 `key` 应得 AIR = 0（A 类）。

## 5. 判定（取数前写定；全部以 **test 集 + R 档（真人）** 为准，T 档只作补充）

被测组合 = 在 R 档上 AIR 最高且 FIR 合格的「引擎 × 上下文 × 重打分」。

| 规则 | 通过条件 |
|---|---|
| J1（H1） | 被测组合 AIR 比同引擎 C0 + R0 **高 ≥ 20pp**，且 n ≥ 30 个 A 类出现，Wilson 95% 下界仍 > 0 |
| J2（H3） | C5 的 AIR 与 C0 之差 ≤ 5pp，**且** C1 − C5 ≥ 15pp |
| J3 | FIR ≤ C0 + 3pp，且中性句插入数 ≤ 0.05 / 句 |
| J4（H2） | C3 的 FIR 或插入数 **高于** C1（方向即可；这条是对既有读数的复核，不通过只登记） |
| J5（H4） | R2 的 AIR 比 R1 高 ≥ 10pp 且 FIR ≤ R1 + 3pp；R3、R4 各自不优于 R2（否则对应成分无必要） |
| J6（H5） | 两层叠加的净收益 ≥ 任一单层 + 5pp |
| J7（H6） | 标记 recall@10% ≥ 0.6，且高于「标识符形且未命中」规则基线 |

**读数如何改变决定：**

| 结果 | 决定 |
|---|---|
| J1、J2、J3 过 | 提案阶段 4 的「上下文进 ASR」提前为独立适配器任务，词源按 C1 / C2 的形态裁剪后喂 |
| J1 不过、J5 过 | 不换识别器，只加重打分（提案阶段 1–2 加音近键） |
| J1 过、J3 不过 | 上下文有效但误伤不可接受 → 只在 UI 层把「被上下文改动的词」标出来可撤销，不静默生效 |
| J2 不过 | 整条「上下文」结论作废，回到纯文本层 |
| 都不过 | 同音歧义无法在文本层以外解决，需要用户在 UI 里手点（提案 5.3 成为主路径） |

## 6. 探针门（取数前，不入数据）

1. **E3/E4 能否在本机跑起来。** 这台机器 128 核、246 GB 内存、**无 GPU**、当前未装 torch。记录安装耗时、模型体积与许可证、10 秒音频的 CPU 实时因子。RTF > 1 的话，主实验按条件数估算总耗时，超过 3 小时就把 E4 降为只跑 C0/C1/C5。
2. **`context` 是否真的被承认**：沿用 2026-09-23 的判法——同一音频、同一 context 文本、仅把靶词替换成无关词，看输出是否移动；并实测「放进 context 的靶词在没有任何声学证据时会不会被凭空吐出」（空音频 / 纯噪声 + C1，**吐出就是 J3 的前兆**）。
3. **E5 / E6** 是否有英文标识符能力：用 10 条 B 类句 C0 先看一眼；明显崩（中文模型把英文全音译）则登记后退出，不进主实验。
4. **音素表**：CMUdict 许可证与大小；对 40 个靶词的发音覆盖率（缺的人工补，补了要登记）。
5. **TTS 发音校验**：每个 A 类靶词，每种音色，用与靶词无关的识别器听写，确认强制 /kiː/ 变体确实被念成 /kiː/。
6. **用户发音**：先请用户念 5 个 A 类词，人读确认他念的是什么（`quay` 念 /kiː/ 还是 /kweɪ/？）。**这一条决定 H1 在真实世界里是否有意义**：若用户本来念 /kweɪ/，ASR 的主要问题是「陌生词」而不是「同音」，对应的结论与方案都不同。

探针结果写入 `PROBE.md`，任何一条使计划变动都登记为偏差。

## 7. 执行规程

- 串行；Groq / DashScope 请求按进程节流（README 协议第 7 条）。
- 每条结果落盘缓存，分析脚本只读缓存重算（第 8 条）。
- 配对比较：所有条件在同一批片段上；某条件缺一条就缩小配对集合，每个读数旁边打印 n。
- 预算闸：云端合计 ≤ ¥3（DashScope 逐段识别约 ¥0.01 / 条脚本的量级，230 条 × 若干条件远低于此；Groq 免费额度内）；本机推理不计费但记录耗时。
- 人读（强制）：从 test 集 R 档里按「引擎 × 条件」分层抽 40 条输出，三位盲评（不看引擎、条件、是否重打分），只回答「靶词对不对 / 有没有被误改 / 有没有凭空插入」；机械与人读不一致 > 10% 时，以人读为准并修谓词（登记为偏差）。
- 先在 dev 集上定阈值、写下来、提交；再一次性跑 test。

## 8. 已知偏差与局限（取数前登记）

1. **n 很小。** R 档只有用户一个人的约 90 条；任何小于约 15pp 的差异不应解读；只报 Wilson 区间。
2. **单说话人、单设备链路。** 不能外推到别的用户；这个实验回答的是「这位用户 + 这套项目词」的问题。
3. **靶词与模板来自作者读过的历史**，有「为已知答案出题」的倾向；dev/test 按模板和靶词双切分是为了缓解，不是消除。
4. **TTS 与真人分开报。** T 档的 FIR / AIR 不得写进结论的主表。
5. **「Qwen3-ASR 的 `context` 接口」「Paraformer 英文能力」「sherpa 双语模型」均来自外部描述，尚未在本机验证**；以探针门为准。
6. **音近键对中文转写体（把 /kiː/ 写成「克伊」）可能无能为力**，这类输出在 R 档里出现的比例未知。
7. **R2 的权重是先验设定，不是拟合值。** 如果探针 / dev 显示权重明显不合理，只能改阈值，不能改权重；权重要改就开新一轮预注册。
8. 本实验**不**评价书面化、标点、数字写法（已有记录覆盖），也不评价延迟与成本的产品取舍，只报读数。
